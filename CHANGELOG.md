- Fix the catalog review findings: `/admin` is denied by a global guard (a forgotten decorator can no longer open a route), error logs carry no SQL or parameters, oversized or malformed bodies answer 413/400, the seed refuses non-throwaway databases (the example database is now `fluxkit_dev`), malformed store slugs answer 400/404, the store hides option values and images that no active variant sells (ADR 0007), long titles no longer exhaust slug suffixes, generated variants of live products with required variant attributes start inactive (ADR 0008; core `publishPreconditions` asks required variant attributes only of active variants), NUL and lone surrogates in free-text fields answer 400, deeply nested attribute values answer 400.
- Add admin auth database schema (`admin_user`, `admin_session`; migration `0002_admin_auth` with down script, constraint tests on real Postgres).
- Add admin auth infrastructure (plan step 3a): scrypt password hasher, Postgres-backed session service, session-cookie authenticator replacing the deny-all default, `@RequirePermission`/`@PublicAdminRoute` with a default permission by HTTP method, `forbidden` (403) problem code, required `X-Fluxkit-CSRF: 1` header on state-changing admin requests, and `ADMIN_COOKIE_SECURE`, `ADMIN_SESSION_IDLE_MINUTES`, `ADMIN_SESSION_MAX_HOURS`; login endpoints follow in step 3b.
- Add admin auth endpoints (plan step 3b): `POST /admin/auth/login`, `logout`, `GET /admin/auth/me`, `POST /admin/auth/change-password`, owner-only `/admin/users` (list, create, get, patch role or activity, reset password), per-account lockout and a per-IP login limit, `@AuthenticatedAdminRoute`, and the `too_many_requests` (429) problem code with `Retry-After`.
- Add `pnpm admin:create` (plan step 4): creates the first owner (or another admin user) from the command line, password from `ADMIN_PASSWORD` or a no-echo prompt, never from an argument, refuses an existing email; update the auth contract (`docs/contracts/api.md`), README quick start and Admin sign-in, and the stale auth notes in `docs/api/catalog.md`.
- Harden admin auth after the independent review: no process crash on a dropped database connection, query errors never logged with SQL or parameters, session created inside the login transaction, expired sessions cleaned up, IPv6 login limit per /64, `Cache-Control: no-store` on `/admin`, new `pnpm admin:unlock --email <address>` (ADR 0010).
- Add `pnpm db:migrate`: applies the pending migrations of `apps/api/drizzle` to `DATABASE_URL` in order, forward only (no rollback, no schema change), idempotent, under a Postgres advisory lock, refuses a database that is ahead of the code.
- Add the core money module (`packages/core/src/pricing`, pricing plan step 1): integer minor units with ISO 4217 currencies, exact add, subtract, multiply by quantity, percentages in basis points with four rounding modes computed with BigInt, and strict decimal string parsing and formatting; ADR 0011 records the money and stock model.
- Add core price rules (`validatePrice`, `pickSellablePrice`) and stock rules (`availabilityOf`, reserve, release, expire, commit and adjustment decisions), and a `price_missing` publish violation for active variants without a shop-currency price (`VariantSnapshot.hasShopPrice`; the API passes a labelled placeholder until pricing step 4); pricing plan step 2.
- Add the pricing and inventory schema (pricing plan step 3, ADR 0012): migration `0003_pricing_inventory` with down script adds `price`, `location` (seeded with the default `main`), `inventory_level`, `stock_movement` (append-only trigger), `reservation` and the `variant.track_inventory` / `variant.allow_backorder` columns (existing variants: tracked, no backorder).
- Add the admin price endpoints (pricing plan step 4a): `GET|PUT|DELETE /admin/products/{id}/variants/{variantId}/prices[/{currency}]` and bulk `PUT /admin/products/{id}/prices` (integer minor units, core `validatePrice`, product row lock, shop-currency price of a live variant cannot be deleted), config `SHOP_CURRENCY`, `PRICES_INCLUDE_TAX`, `LOW_STOCK_THRESHOLD`, and the real `price_missing` publish rule: publishing a product with an active variant without a shop-currency price now answers 400, and switching a variant on in a published product answers 409 `price_missing`. `pnpm seed` writes a flat placeholder price per demo variant so it can still publish (real demo prices: step 6).
- Add the admin inventory API (pricing plan step 4b): `trackInventory` and `allowBackorder` on variant create, patch and every admin variant response (variants of a product type that does not ship start untracked), `GET /admin/locations`, `GET /admin/products/{id}/variants/{variantId}/inventory`, `POST .../inventory/adjustments` (core `decideAdjustment` under the product and level row locks, append-only `stock_movement` row with the acting admin) and `GET .../inventory/movements`; add `ReservationsService` (`reserve`, `release`, `commit`, `expireDue`; no HTTP route, level row lock, concurrency tests); docs `docs/api/inventory.md`. No schema change.

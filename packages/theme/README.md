# @fluxkit/theme

Design tokens (`tokens.css`, `light` and `dark`, plus the opt-in `system` mode block that follows the device only for `data-theme="system"`), their Tailwind mapping (`tailwind.css`), the fork-owned overrides files (`brand-overrides.css` for the storefront, `admin-overrides.css` for the admin; empty upstream) and `emailTheme` / `themeColors` (literal copies of the effective light values and backgrounds, guarded against drift). Rebranding = token values in `brand-overrides.css` plus the two literal copies `email-theme.ts` and `theme-color.ts` (their specs print the values); `tokens.css` stays upstream's.

- Contract and contrast rules: `docs/contracts/theme-tokens.md` ("Storefront overrides" for the cascade). `pnpm --filter @fluxkit/theme test` checks that non-colour tokens are defined once (light block), that dark and system hold the same colour and shadow names, the Tailwind mapping, the shape of `brand-overrides.css` and that only the storefront imports it, WCAG contrast of the documented pairs on the EFFECTIVE values (storefront: tokens plus `brand-overrides.css` in light, dark and system; admin: tokens plus `admin-overrides.css`), mail and theme colours against those values, and the design guard. It runs twice: on the real files (`vitest.config.ts`) and on filled fork fixtures in `src/fork-fixture/` (`vitest.brand-fork.config.ts`, canary `src/fork-run.spec.ts`).
- Use 6-digit hex colors in `tokens.css` and the overrides files; the contrast test fails on any other format.
- Radii are roles (`--fk-radius-control|card|panel|overlay|media`, utilities `rounded-control|card|panel|overlay|media`; literal rem values): rebrand a role, not a size step. `rounded-full` is a shape, not a role. The size steps `--fk-radius-sm|md|lg` stay for forks and for the 0.25rem parts in the guard's exception list (`docs/contracts/theme-tokens.md`, "Radius roles").

File map: `docs/files/theme.md`.
- Use `border-input` (not `border`) for the border of anything that is an input; the contrast test checks it at 3:1 and fails for a component pair that is not covered.

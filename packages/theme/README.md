# @fluxkit/theme

Design tokens (`tokens.css`, `light` and `dark`, plus the opt-in `system` mode block that follows the device only for `data-theme="system"`), their Tailwind mapping (`tailwind.css`), the fork-owned overrides files (`brand-overrides.css` for the storefront, `admin-overrides.css` for the admin; empty upstream) and `emailTheme` / `themeColors` (literal copies of the effective light values and backgrounds, guarded against drift). Rebranding = token values in `brand-overrides.css` plus the two literal copies `email-theme.ts` and `theme-color.ts` (their specs print the values); `tokens.css` stays upstream's.

- Contract and contrast rules: `docs/contracts/theme-tokens.md` ("Storefront overrides" for the cascade). `pnpm --filter @fluxkit/theme test` checks that non-colour tokens are defined once (light block), that dark and system hold the same colour and shadow names, the Tailwind mapping, the shape of `brand-overrides.css` and that only the storefront imports it, WCAG contrast of the documented pairs on the EFFECTIVE values (storefront: tokens plus `brand-overrides.css` in light, dark and system; admin: tokens, the light rule of `brand-overrides.css`, then `admin-overrides.css`, and no storefront web-font variable without an internal fallback in its font tokens), mail and theme colours against those values, and the design guard. It runs twice: on the real files (`vitest.config.ts`) and on filled fork fixtures in `src/fork-fixture/` (`vitest.brand-fork.config.ts`, canary `src/fork-run.spec.ts`).
- Use 6-digit hex colors in `tokens.css` and the overrides files; the contrast test fails on any other format.
- Radii are roles (`--fk-radius-control|card|panel|overlay|media`, utilities `rounded-control|card|panel|overlay|media`; literal rem values): rebrand a role, not a size step. `rounded-full` is a shape, not a role. The size steps `--fk-radius-sm|md|lg` stay for forks and for the small marks in the guard's exception list (`docs/contracts/theme-tokens.md`, "Radius roles").

File map: `docs/files/theme.md`.
- Use `border-input` (not `border`) for the border of anything that is an input; the contrast test checks it at 3:1 and fails for a component pair that is not covered.

- Playful defaults (2026-11-14): cream/ink palette, tomato actions, rounded controls/cards/overlays (1.5rem), panels/media (1rem), scale radii 0.375/0.75/1.5rem and ink offset shadows (3/5/6px, no blur). Type scale and spacing unit stay unchanged.
- Body and display stacks start with `var(--font-template-sans, ui-sans-serif)`: storefront Rubik comes from `lib/template-fonts.ts`; the admin uses the internal fallback. A fork's light font overrides win; no template font is downloaded once neither stack names it (`preload: false`).
- Motion: fast/base/slow durations (150/250/400ms), standard/emphasized/spring easings; `duration-fast|base|slow`, `ease-standard|emphasized|spring`, and plain transition utilities follow tokens. `html:root` zeroes durations under reduced motion, beating fork overrides; do not wait solely for transition/animation end events at 0ms. Retune in the light rule of the fork-owned overrides file.

# packages/providers

Payment, shipping and email provider plugins, one package per provider. Each provider's specs run the core contract check (`checkShippingProviderContract`, `checkEmailProviderContract`, `checkPaymentProviderContract`). A shipping provider declares `"fluxkit": {"provider": "<code>", "kind": "shipping"}`, exports `providerModule` and is loaded by `apps/api` only when its code is in `SHIPPING_PROVIDERS_ENABLED` (`docs/contracts/config.md`, "Shipping provider package contract"). Core and apps never import a provider (`core-must-not-import-providers`, `apps-must-not-import-providers`).

- `README.md` - rules for provider packages.
- `_fake/` - `@fluxkit/provider-fake`, shipping provider `fake`. TEST-ONLY: deterministic, in-memory, no network; never enable it in a real shop. Fixture for the provider matrix (`scripts/feature-matrix.sh providers-*`) and for tests of the shipping module; safe to delete.
  - `README.md` - purpose, variables (none), the failure hook, how to remove it.
  - `package.json` - the manifest (`fluxkit.provider` = `fake`, `fluxkit.kind` = `shipping`); depends on `@fluxkit/core` for the port, never on `apps/api`.
  - `src/fake-shipping-provider.ts` - `FakeShippingProvider`: implements `ShippingProviderPort` with fixed cities and pickup points (all in `UA`, also found by ref with `findPickupPoint`), a fixed estimate, numbered waybills kept in memory, and the test hooks `failNext`, `setTrackingStatus`, `reset`, `waybillCount`; `validateSettings` accepts any object; a label needs the waybill's matching number. Must NOT read the environment, the clock, a random source or the network.
  - `src/index.ts` - `FakeShippingProviderModule` and the entry export `providerModule`.
  - `src/fake-shipping-provider.spec.ts` - unit tests of the provider and the hooks (they disappear with the package).
- `_fake-email/` - `@fluxkit/provider-fake-email`, email provider `fake` (the code exists once per kind). TEST-ONLY: in memory, no network, no clock, no randomness; never enable it in a real shop (`loadEnv` refuses `EMAIL_PROVIDER=fake` in production). Fixture for the email matrix modes (`providers-email-fake`, `providers-email-none`, `providers-deleted`) and for tests of the email module; safe to delete.
  - `README.md` - purpose, variable (`FAKE_EMAIL_CAPTURE_FILE`), the capture mailbox and failure hooks, how to remove it.
  - `package.json` - the manifest (`fluxkit.provider` = `fake`, `fluxkit.kind` = `email`); depends on `@fluxkit/core` only.
  - `src/fake-email-provider.ts` - `FakeEmailProvider`: implements `EmailProviderPort`; deduplicates by idempotency key like Resend (same body replays the first answer, another body is `idempotency_conflict`), refuses the recipient `refused@...`, answers `not_sent` for an aborted signal or a message that fails `validateOutgoingEmail`; hooks `failNext`, `mailbox`, `requests`, `reset`. Must NOT read the environment, the clock, a random source or the network.
  - `src/index.ts` - `FakeEmailProviderModule` (its factory reads `FAKE_EMAIL_CAPTURE_FILE`), `parseFakeEmailCaptureFile` and the entry export `providerModule`.
  - `src/fake-email-provider.spec.ts` - runs `checkEmailProviderContract`, the hooks and the capture file (they disappear with the package).
- `_fake-payment/` - `@fluxkit/provider-fake-payment`, payment provider `fake` (the code exists once per kind). TEST-ONLY: in memory, no network, no wall clock, no randomness, charges nothing; never enable it in a real shop (`loadEnv` refuses `PAYMENT_PROVIDERS_ENABLED=fake` in production). Fixture for the payment matrix modes (`providers-payment-fake`, `providers-payment-none`, `providers-deleted`) and for tests of the payment module; safe to delete.
  - `README.md` - purpose, variables (none), the hooks, the webhook signature scheme, how to remove it.
  - `package.json` - the manifest (`fluxkit.provider` = `fake`, `fluxkit.kind` = `payment`); depends on `@fluxkit/core` only.
  - `src/fake-payment-provider.ts` - `FakePaymentProvider`: implements the whole `PaymentProviderPort` (numbered invoices on a reserved `.invalid` page host, facts with a logical `modifiedAt`, `invalidatePayment`, refunds deduplicated by refund id and listed by `getPayment`, `verifyWebhook` over the documented HMAC scheme); create is NOT idempotent (Monobank M5); hooks `failNext` (operation, reason, codes, `retryAfterSeconds`, `times`, `afterEffect`, `hang`, `throws`), `process`, `complete`, `fail`, `expire`, `reverse`, `addExternalRefund`, `setRefundMode`, `settleRefund`, `webhookFor`, `invoices`, `invoice`, `requests`, `reset`. Must NOT read the environment, the wall clock, a random source or the network.
  - `src/webhook.ts` - the fake signature scheme: header `x-fake-signature` = hex HMAC-SHA256 of the raw body with a fixed public test key (`signFakeWebhook`, `fakeWebhookInput`, `fakeWebhookSignatureMatches`, constant-time compare). Not Monobank's scheme (ECDSA).
  - `src/index.ts` - `FakePaymentProviderModule` and the entry export `providerModule`.
  - `src/fake-payment-provider.spec.ts` - runs `checkPaymentProviderContract`, the transitions, refunds, webhooks and failure hooks (they disappear with the package).
- `monobank/` - `@fluxkit/provider-monobank`, payment provider `monobank`: Monobank acquiring "Plata by mono" over `https://api.monobank.ua` with `X-Token` (ADR 0032 decision 15, payments plan step 7). UAH only. Built and tested against a local stub only (live check S1 not run). Safe to delete (`scripts/feature-matrix.sh providers-deleted`).
  - `README.md` - purpose, flag, variable (`MONOBANK_TOKEN`), the requests, the answer and fact mapping, webhook verification, capabilities, what is unverified, the S1 steps, tests, how to remove it.
  - `package.json` - the manifest (`fluxkit.provider` = `monobank`, `fluxkit.kind` = `payment`); depends on `@fluxkit/core` and `zod` 4.6.7 only.
  - `src/index.ts` - `MonobankPaymentProviderModule` (its factory parses `MONOBANK_TOKEN`, so a missing or malformed token stops the startup) and the entry export `providerModule`. Must NOT call Monobank at startup.
  - `src/config.ts` - `parseMonobankEnv` (20 to 256 visible ASCII characters), the origin, route and header constants (no URL variable). Must NOT echo a value in an error.
  - `src/http.ts` - `MonobankHttp`: the only network access (Node `fetch` to the fixed routes, `redirect: "error"`, the token only in `X-Token`, the invoice id as the only query value, the caller's signal as the only time limit, answers capped at 64 KiB while streaming). Must NOT log, retry or name another host.
  - `src/invoice.ts` - `createBodyOf` (the create body; local refusals), `basketOrderOf` (omitted unless every line is right), `readCreateAnswer` with the page host allow-list `MONOBANK_PAGE_HOSTS` (M23, assumed `pay.mbnk.biz`), `readCancelAnswer`, `factOf` (status answer or webhook body to `ProviderPaymentFact`: statuses, `cancelList` refunds, card system and last 4). Must NOT keep `errText`, `failureReason`, a card mask, `rrn` or `approvalCode`.
  - `src/answer-map.ts` - `mapMonobankError` (status first, documented `errCode` refines it), `MONOBANK_ERROR_CODES`, `retryAfterSecondsOf`, `malformedAnswer`, `failureOfExchange`. Must NOT keep a message text or an undocumented code.
  - `src/signature.ts` - `MonobankKeyCache` (per-process key, refetch only after a failed verification and at most once per 60 s, single flight), `publicKeyOf` (EC P-256 only), `signatureOf`, `signatureVerifies` (`node:crypto` over the raw bytes). Must NOT take a key from a webhook.
  - `src/monobank-provider.ts` - `MonobankPaymentProvider` (implements `PaymentProviderPort`; capabilities; one request per operation; verification before parsing; one warning per failure with codes only, a `403` once per process as an error). Must NOT repeat a request or log the token, a body or a URL.
  - `src/test-support/` - TEST ONLY (excluded from the build): `stub-monobank.ts` (a local Monobank stand-in on 127.0.0.1 with invented data and its own P-256 key: records every request, signs webhooks, no create idempotency and no `extRef` dedupe, echoes the token and card masks in its error texts), `fixtures.ts` (invented inputs, `providerOn`, a test clock, signals, a recording logger), `documented-example.ts` (the documented key, `X-Sign` and body, M12), `no-network.ts` (the Vitest setup file that refuses and reports any request to another host).
  - `src/*.spec.ts` - request shapes, answer mapping, operations and fact mapping, webhook verification (documented vector, rotation, throttle), the transport, secrets, configuration, the module, the contract check, the stub's strictness, the no-network guard and static source checks.
- `nova-post/` - `@fluxkit/provider-nova-post`, shipping provider `nova_post`: the Nova Post REST API `v.1.0` (JWT; ADR 0030, plan `docs/plans/2026-10-25-nova-post-plugin.md`). Safe to delete (`scripts/feature-matrix.sh providers-deleted`).
  - `README.md` - purpose, flag, variables (`NOVA_POST_API_KEY`, `NOVA_POST_ENVIRONMENT`), settings, the operation mapping, limits, tests, how to remove it.
  - `package.json` - the manifest (`fluxkit.provider` = `nova_post`, `fluxkit.kind` = `shipping`); depends on `@fluxkit/core` and `zod` 4.6.7 only.
  - `src/index.ts` - `NovaPostShippingProviderModule` (its factory parses the variables, so a missing key stops the startup; logs the environment) and the entry export `providerModule`. Must NOT call Nova Post at startup.
  - `src/config.ts` - `parseNovaPostEnv` and the two base-URL constants (no URL variable). Must NOT echo a value in an error.
  - `src/http.ts` - `NovaPostHttp`: the only network access (Node `fetch`, `redirect: "error"`, raw-JWT header, caller signal plus a core ceiling, size caps while reading), the JWT cache (exp minus 5 minutes, single flight, one refresh and repeat on `401` except where the caller forbids it), `carrierCodesOf` (status, keys that look like field paths (`fieldPathOf`), snake_case values; never text or a key that may echo a value), `namesRequestField`, `NovaPostCallError`. Must NOT log a URL with a query, a body, the key or the JWT.
  - `src/nova-post-provider.ts` - `NovaPostShippingProvider` (implements `ShippingProviderPort`; each operation's request, answer reading and failure mapping); `novaPostPhone`. Must NOT repeat `POST /shipments`, pick a point the carrier did not answer for its id, answer `null` from `findWaybill` without certainty (a list that changed while read is `list_changed`), or let a city list outlive its time budget (`NOVA_POST_LIST_DEADLINE_MS`, `NOVA_POST_LIST_STOP_MS`).
  - `src/schemas.ts` - zod schemas of the answers read (loose objects, strict used fields).
  - `src/settings.ts` - the sender profile schema, `novaPostSettingsIssues` (`validateSettings`) and `parseNovaPostSettings`.
  - `src/status-map.ts` - `NOVA_POST_STATUS_TABLE` and `mapNovaPostStatus` (the documented code table; `1` and `2` observed).
  - `src/test-support/` - TEST ONLY (excluded from the build): `stub-carrier.ts` (a local Nova Post stand-in on 127.0.0.1 with invented data that records every request, refuses what production refused and can answer slowly, `latencyMs`), `fixtures.ts` (settings, a waybill request, `providerOn`), `no-network.ts` (the Vitest setup file that refuses and reports any request to another host; it marks the wrapped `fetch` so `no-network-wired.spec.ts` can see it is active).
  - `src/*.spec.ts` - request shapes, JWT and errors, `findWaybill` paging, operations, status table, settings, configuration, secrets in logs, the module, the contract check, the strictness of the stub carrier (`stub-carrier.spec.ts`), the no-network guard and that it is wired for every file (`no-network-wired.spec.ts`), and a static check of the sources (they disappear with the package).
- `resend/` - `@fluxkit/provider-resend`, email provider `resend`: Resend `POST https://api.resend.com/emails` (ADR 0031 decision 17, email plan step 6). Built and tested against a local stub only (live check S1 not run). Safe to delete (`scripts/feature-matrix.sh providers-deleted`).
  - `README.md` - purpose, flag, variable (`RESEND_API_KEY`), the request, the answer mapping, what is unverified, the S1 steps, tests, how to remove it.
  - `package.json` - the manifest (`fluxkit.provider` = `resend`, `fluxkit.kind` = `email`); depends on `@fluxkit/core` and `zod` 4.6.7 only.
  - `src/index.ts` - `ResendEmailProviderModule` (its factory parses `RESEND_API_KEY`, so a missing or malformed key stops the startup) and the entry export `providerModule`. Must NOT call Resend at startup.
  - `src/config.ts` - `parseResendEnv` (`re_` + 16 to 256 visible ASCII characters), the endpoint and `User-Agent` constants (no URL variable). Must NOT echo a value in an error.
  - `src/http.ts` - `ResendHttp`: the only network access (one `POST /emails` with Node `fetch`, `redirect: "error"`, `Bearer` key, `User-Agent`, `Idempotency-Key`, the caller's signal as the only time limit, answers capped at 64 KiB while streaming); the endpoint is the constant, only a test may name a stub on 127.0.0.1. Must NOT log, or put the key anywhere but the `Authorization` header.
  - `src/request.ts` - `resendBodyOf`: the JSON body (`from`, `to` array of one, `subject`, `html`, `text`, `reply_to` (R3, assumed), `tags`). Must NOT add `headers`, `cc`, `bcc` or anything from data.
  - `src/answer-map.ts` - `mapResendAnswer` (status first, documented error names refine it; an unreadable 2xx is `unavailable`), `RESEND_ERROR_NAMES`, `resendErrorNameOf`, `retryAfterSecondsOf` (seconds only). Must NOT keep a message text or an undocumented name.
  - `src/resend-provider.ts` - `ResendEmailProvider` (implements `EmailProviderPort`: local validation as `not_sent`, one request, the mapping, one warning per failure with codes only). Must NOT repeat a request or log an address, subject, body or the key.
  - `src/test-support/` - TEST ONLY (excluded from the build): `stub-resend.ts` (a local Resend stand-in on 127.0.0.1 with invented data: records every request, models idempotency, refuses unknown body members, echoes addresses and key fragments in its error texts on purpose), `fixtures.ts` (an invented message, `providerOn`, signals), `no-network.ts` (the Vitest setup file that refuses and reports any request to another host).
  - `src/*.spec.ts` - request shape, status mapping and `retry-after`, idempotency, transport (size cap, aborts, network, endpoint), hostile values, secrets, configuration, the module, the contract check, the stub's strictness, the no-network guard and its wiring, a static check of the sources (they disappear with the package).

# packages/theme

- `src/tokens.css` - the design tokens for the `light` and `dark` themes (the one place to rebrand), each with its `color-scheme`; non-colour tokens only in the light block (dark inherits them from `:root`), and the opt-in `system` block (`@media (prefers-color-scheme: dark)` for `[data-theme="system"]` only: the dark colours and shadows; design batch B). Colors are 6-digit hex (the contrast test requires it). Must NOT style `:root` inside a media query (the admin would follow the device).
- `src/tailwind.css` - maps tokens to Tailwind semantic utilities (`success`, `warning` and `ring` included; `font-display` since 2026-11-08; the radius roles `rounded-control|card|overlay|media` since 2026-11-09, next to the kept steps `rounded-sm|md|lg`).
- `src/index.ts` - theme names and default, `themeModes` / `ThemeMode` (`light`, `dark`, `system`: what a page may put into `data-theme`); re-exports `emailTheme`.
- `src/token-blocks.ts` - `parseTokenBlocks`, `tokenBlock`, `themeSelectors`, `darkSchemeMedia`: reads `tokens.css` into its rule blocks for the specs; throws on any other rule shape. Not exported from the package entry.
- `src/email-theme.ts` - `emailTheme` (ADR 0031 decision 14, email plan step 2): deeply frozen email-safe values for inline styles in mail (mail clients do not support CSS variables): the light colors, font stacks and radii of `tokens.css` (radii in px), plus mail-only spacing, font sizes, line height and content width (600). Contract: `docs/contracts/theme-tokens.md`, "Email theme". Read by `apps/api` (`src/email/templates/email-theme.ts`, a workspace dependency since email plan step 5). Must not hold a value that is not a token's light value except the mail-only groups.
- `src/email-theme.spec.ts` - guard: every `emailTheme` color, font and radius equals the light token of the same name (rem to px), every light token is in `emailTheme` or listed as not used in mail with a reason (`border-input`, `ring`, `danger-foreground`, the accent pair, the display font, the four radius roles (mail keeps `emailTheme.radius`), the three shadows, the type scale and the spacing unit); font stacks are compared without `var(--font-*)` entries (a fork web font), only 6-digit hex colors and px sizes, no CSS variables, no characters that could leave a `style` attribute, deeply frozen.
- `src/theme.spec.ts` - non-colour tokens (fonts, radii, type scale, spacing) are defined only in the light block, the radius roles are literal rem values (2026-11-09, T3), the dark block holds exactly light's colour and shadow names (2026-11-08, T4), every mapped token exists in light, every color token is mapped; exactly the light, dark and system blocks exist, the system block equals the dark block byte for byte, media rules match `[data-theme="system"]` only, `color-scheme` per block; the block parser.
- `src/contrast.spec.ts` - WCAG 2.x contrast of the documented token pairs in both themes and in the system mode on a dark device (`docs/contracts/theme-tokens.md`), including `border-input` (3:1) and, unconditionally, the accent pair (2026-11-08), and a scan of the class strings of `packages/ui`, `apps/storefront` and `apps/admin/src` (one list of scanned roots; each must hold at least one source file) that fails when a component uses a color pair that is neither listed nor declared decorative.
- `src/design-guard.spec.ts` - fails if `packages/ui`, `apps/storefront` or `apps/admin` contain hex/rgb colors, Tailwind palette colors, color utilities that are not token names, arbitrary values or inline styles; also checks that every scanned root holds files (the admin app and the admin components of `packages/ui` included) and that its own patterns catch known violations. Since design batch A (2026-11-03): `tailwind.css` maps the type scale, the spacing unit, the radii and the shadows to tokens, and no non-spec source uses a font size, radius or shadow outside those scales (`text-5xl`, `rounded-xl`, `shadow-md` fail). Since 2026-11-08: the font stacks (`sans`, `mono`, `display`) are mapped, and every `<h1>`-`<h6>`, `<Heading>` and `<legend>` with classes in `packages/ui` and `apps/storefront` uses a `textStyles` role (visibility-only classes pass; the admin is not scanned: known limit). Since 2026-11-09 (T3): radii only as roles (`rounded-control|card|overlay|media`, plus `rounded-full` and `rounded-none`), the role mappings are demanded, `@apply` rules of CSS files are scanned too, and `rounded-sm|md|lg` pass only through `radiusExceptions` (file, class, exact count, reason; a stale entry fails).
- `src/tokens.css` also holds (2026-11-03) the type scale (`--fk-font-size-*`, `--fk-line-height-*`), the spacing unit (`--fk-space-unit`) and the elevations `--fk-shadow-raised` and `--fk-shadow-overlay`; `src/email-theme.spec.ts` lists them as not used in mail.

# packages/theme

- `src/tokens.css` - the template's design tokens for the `light` and `dark` themes (a fork rebrands in `src/brand-overrides.css`, not here), each with its `color-scheme`; non-colour tokens only in the light block (dark inherits them from `:root`), and the opt-in `system` block (`@media (prefers-color-scheme: dark)` for `[data-theme="system"]` only: the dark colours and shadows; design batch B). Colors are 6-digit hex (the contrast test requires it). Must NOT style `:root` inside a media query (the admin would follow the device).
- `src/admin-overrides.css` - FORK-OWNED, empty upstream (a comment with an example; ADR 0047): token overrides (and a client `@font-face`) for the admin alone, exported as `@fluxkit/theme/admin-overrides.css` and imported last by `apps/admin/src/styles.css` only. Upstream never edits it after its creation. Must NOT be imported or named by shipped sources of the storefront, `packages/ui` or the other theme files (specs may read it), and must not hold a dark, `system` or `prefers-color-scheme` rule (`apps/admin/src/theme-isolation.spec.ts`). Not scanned by the design guard (it may hold hex); since 2026-11-10 `contrast.spec.ts` checks the admin's effective values (tokens plus this file).
- `src/brand-overrides.css` (PR-I2a, 2026-11-10) - FORK-OWNED, empty upstream (a comment with the cascade rules and an example): the storefront's token overrides, exported as `@fluxkit/theme/brand-overrides.css` and imported LAST by `apps/storefront/src/app/globals.css` and by `apps/admin/src/styles.css` before `admin-overrides.css` (the admin follows the shop, ADR 0047; only the light rule matches its page). Upstream never edits it after its creation. Holds only the three theme rules of `tokens.css` in their order (colours and shadows in all three, everything else in light; dark and system rules allowed, unlike the admin's file). Must NOT be imported or named by other shipped sources of the admin, `packages/ui` or the other theme files (specs may read it). Not scanned by the design guard.
- `src/brand-overrides.spec.ts` - the storefront imports it last, the admin after `tailwind.css` and before `admin-overrides.css` (option B), the package export, the shipped-source scan (and the scan itself), the token values of `tokens.css` and the admin overrides (`valueProblems`: 6-digit hex colours, lengths, shadows, font lists, no empty value, no `!important` in any spacing), and the file's shape (`overridesProblems`: exact selector spelling, allowed selectors and order, existing tokens only, no `!important`, light colours also set for dark, system equal to dark) on the file the run reads. `src/brand-overrides.upstream.spec.ts` - UPSTREAM-ONLY, FORK-DELETABLE: the upstream file holds no rule.
- `src/theme-run.testing.ts` - test support (not a spec, not built): reads `tokens.css` and the overrides files the vitest config provides, and gives the specs the effective tokens of the storefront (four page states) and the admin (light).
- `vitest.config.ts` / `vitest.brand-fork.config.ts` - the two theme runs (`pnpm test` runs both): the real overrides files, and the filled fixtures of `src/fork-fixture/` (`brand-overrides.css`: the A1 "Verde Kopi" rebrand; `admin-overrides.css`: a neutral admin with a client `@font-face`; `email-theme.ts` and `theme-color.ts`: the literal copies updated for that rebrand, put in place of the real files by aliases), without the `*.upstream.spec.ts`. `src/fork-run.spec.ts` - canary: each run reads its own files and literal copies. `src/fork-fixture/` is test-only (excluded from `tsconfig.build.json`).
- `src/tailwind.css` - maps tokens to Tailwind semantic utilities (`success`, `warning` and `ring` included; `font-display` since 2026-11-08; the radius roles `rounded-control|card|panel|overlay|media` since 2026-11-09, next to the kept steps `rounded-sm|md|lg`).
- `src/index.ts` - theme names and default, `themeModes` / `ThemeMode` (`light`, `dark`, `system`: what a page may put into `data-theme`); re-exports `emailTheme`.
- `src/token-blocks.ts` - `parseTokenBlocks`, `tokenBlock`, `themeSelectors`, `darkSchemeMedia`: reads `tokens.css` (and the overrides files) into rule blocks for the specs; throws on any other rule shape. `effectiveTokens` (2026-11-10): the cascade of blocks in import order for a page state (`storefrontStates`, `adminState`); every known selector has the same specificity, an unknown selector or media throws. Not exported from the package entry.
- `src/email-theme.ts` - `emailTheme` (ADR 0031 decision 14, email plan step 2): deeply frozen email-safe values for inline styles in mail (mail clients do not support CSS variables): the light colors, font stacks and radii of `tokens.css` (radii in px), plus mail-only spacing, font sizes, line height and content width (600). Contract: `docs/contracts/theme-tokens.md`, "Email theme". Read by `apps/api` (`src/email/templates/email-theme.ts`, a workspace dependency since email plan step 5). Must not hold a value that is not a token's light value except the mail-only groups.
- `src/theme-color.ts` (PR-E2, plan B1) - `themeColors`: `--fk-color-background` of the light and the dark theme as literal colours, for the storefront's `<meta name="theme-color">` (`apps/storefront/src/config/brand.ts` `themeColor: true`); apps may hold no hex colour. `src/theme-color.spec.ts` - guard: both equal the storefront's EFFECTIVE background (tokens plus `brand-overrides.css`) in light, dark and system, a failure prints the literals to write, and the entry point exports them.
- `src/email-theme.spec.ts` - guard: every `emailTheme` color, font and radius equals the storefront's EFFECTIVE light token of the same name (tokens plus `brand-overrides.css`; rem to px; a failure prints the literals to write), every light token is in `emailTheme` or listed as not used in mail with a reason (`border-input`, `ring`, `danger-foreground`, the accent pair, the display font, the five radius roles (mail keeps `emailTheme.radius`), the three shadows, the type scale and the spacing unit); font stacks are compared without `var(--font-*)` entries (a fork web font), only 6-digit hex colors and px sizes, no CSS variables, no characters that could leave a `style` attribute, deeply frozen.
- `src/theme.spec.ts` - the cascade of `effectiveTokens` (an override wins in its mode; a light-only colour override also wins on dark pages; unknown selectors throw), the display-font rule on the storefront's effective light values, the admin web-font guard (no `var(--font-*)` in the admin's effective font tokens; the message names the token to restate in `admin-overrides.css`), non-colour tokens (fonts, radii, type scale, spacing) are defined only in the light block, the radius roles are literal rem values (2026-11-09, T3), the dark block holds exactly light's colour and shadow names (2026-11-08, T4), every mapped token exists in light, every color token is mapped; exactly the light, dark and system blocks exist, the system block equals the dark block byte for byte, media rules match `[data-theme="system"]` only, `color-scheme` per block; the block parser.
- `src/contrast.spec.ts` - WCAG 2.x contrast of the documented token pairs on the EFFECTIVE values (2026-11-10): the storefront (tokens plus `brand-overrides.css`) in light, dark and the system mode on a light and a dark device, and the admin (tokens, the light rule of `brand-overrides.css`, then `admin-overrides.css`) in light (`docs/contracts/theme-tokens.md`), including `border-input` (3:1) and, unconditionally, the accent pair (2026-11-08), and a scan of the class strings of `packages/ui`, `apps/storefront` and `apps/admin/src` (one list of scanned roots; each must hold at least one source file) that fails when a component uses a color pair that is neither listed nor declared decorative.
- `src/design-guard.spec.ts` - fails if `packages/ui`, `apps/storefront` or `apps/admin` contain hex/rgb colors, Tailwind palette colors, color utilities that are not token names, arbitrary values or inline styles; also checks that every scanned root holds files (the admin app and the admin components of `packages/ui` included) and that its own patterns catch known violations. Since design batch A (2026-11-03): `tailwind.css` maps the type scale, the spacing unit, the radii and the shadows to tokens, and no non-spec source uses a font size, radius or shadow outside those scales (`text-5xl`, `rounded-xl`, `shadow-md` fail). Since 2026-11-08: the font stacks (`sans`, `mono`, `display`) are mapped, and every `<h1>`-`<h6>`, `<Heading>` and `<legend>` with classes in `packages/ui` and `apps/storefront` uses a `textStyles` role (visibility-only classes pass; the admin is not scanned: known limit). Since 2026-11-09 (T3): radii only as roles (`rounded-control|card|panel|overlay|media`, plus `rounded-full` and `rounded-none`), the role mappings are demanded, `@apply` rules of CSS files are scanned too, Tailwind v4 `rounded-(...)` and the important marker are refused, variants are stripped without splitting inside `()`/`[]`, and `rounded-sm|md|lg` pass only through `radiusExceptions` (file, class, exact count, reason; a stale entry fails; six 0.25rem parts).
- `src/tokens.css` also holds (2026-11-03) the type scale (`--fk-font-size-*`, `--fk-line-height-*`), the spacing unit (`--fk-space-unit`) and the elevations `--fk-shadow-raised` and `--fk-shadow-overlay`; `src/email-theme.spec.ts` lists them as not used in mail.

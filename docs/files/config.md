# packages/config

- `src/env.ts` - `loadEnv`: validates process env with zod and returns typed `AppEnv` (the media variables `MEDIA_STORAGE_DRIVER` (required in production), `MEDIA_DIR`, `MEDIA_PUBLIC_BASE_URL`, `MEDIA_MAX_BYTES` and `MEDIA_MAX_PIXELS` (ADR 0028; computes paths and URLs only, never touches the file system), locales, admin session limits, the customer session limits and `STORE_COOKIE_SECURE`, `CART_TTL_DAYS`, `ORDER_PAYMENT_TTL_MINUTES` and `ORDER_GUEST_ACCESS_DAYS`, the optional `ORDER_CONTACT_RETENTION_DAYS` (1 to 36 500, no default: job 12 off), `ORDER_TOKEN_SECRET` (at least 32 characters, required when `NODE_ENV=production`, no default; never put it in an error message), `MAX_OPEN_ORDERS` (1 to 50, default 3), `TRUST_PROXY` (0 to 10, default 0), `SCHEDULER_ENABLED` and `SCHEDULER_INTERVAL_SECONDS`, `SHOP_CURRENCY`, `PRICES_INCLUDE_TAX`, `LOW_STOCK_THRESHOLD`). Repeats the supported currency codes of `@fluxkit/core` (this package does not depend on core; a test in `apps/api` asserts the lists are equal) and the defaults of the session and pricing variables.
- `src/media-env.spec.ts` - unit tests of the media variables (`MEDIA_STORAGE_DRIVER`, `MEDIA_DIR`, `MEDIA_PUBLIC_BASE_URL`, `MEDIA_MAX_BYTES`, `MEDIA_MAX_PIXELS`): defaults, production rules, bounds, error messages that never echo values.
- `src/storefront-env.ts` - `loadStorefrontEnv`: validates the storefront's own variables (`API_INTERNAL_URL`, `STOREFRONT_PUBLIC_URL`, `STOREFRONT_IMAGE_HOSTS`, plus `NODE_ENV`) and returns typed `StorefrontEnv`; reads nothing else, so the storefront never needs the API's secrets. Errors name the variable and never echo its value.
- `src/features.ts` - `parseEnabledFeatures`: parses and validates `FEATURES_ENABLED`.
- `src/shipping-providers.ts` - `parseEnabledShippingProviders` and the code pattern: parses and validates `SHIPPING_PROVIDERS_ENABLED` (same rules as the features list, codes may contain underscores); `TEST_ONLY_SHIPPING_PROVIDERS` (`fake`), which `loadEnv` refuses when `NODE_ENV` is production. `src/shipping-providers.spec.ts` tests it.
- `src/email.ts` - `EMAIL_PROVIDER_CHOICES` (`none`, `resend`, `fake`), `DEFAULT_EMAIL_PROVIDER`, `TEST_ONLY_EMAIL_PROVIDERS` (`fake`, refused by `loadEnv` in production) and `parseMailboxVariable`, the `EMAIL_FROM` / `EMAIL_REPLY_TO` mailbox rules (a copy of core `parseMailbox`, because this package does not depend on core; `apps/api` `email-config-parity.spec.ts` runs both on one corpus). `loadEnv` reads `EMAIL_PROVIDER`, `EMAIL_FROM`, `EMAIL_REPLY_TO` and `STOREFRONT_PUBLIC_URL` (the API's reader of the storefront's variable, same origin format) and enforces the combinations (a provider needs a sender; in production also an `https` public URL). Must NOT echo a value in any message and must NOT read `RESEND_API_KEY` (the provider package reads its own key).
- `src/email-env.spec.ts` - unit tests of the email variables: defaults, every combination, the production refusal of `fake`, `https` in production, hostile mailboxes, secrets never in messages.
- `src/payments.ts` - `parsePaymentProvidersVariable` (strict `PAYMENT_PROVIDERS_ENABLED` list: trimmed entries, no empty entry, no duplicate, no case folding; the problem names the rule, never an entry), `PAYMENT_PROVIDER_CODE` (a copy of core's code pattern), `TEST_ONLY_PAYMENT_PROVIDERS` (`fake`, refused by `loadEnv` in production) and `MIN_ORDER_PAYMENT_TTL_MINUTES_WITH_PAYMENT_PROVIDER` (8: core `PAYMENT_INVOICE_WINDOW` margin 3 + minimum 5; `apps/api` `payment-config-parity.spec.ts` asserts the copies equal core). `loadEnv` reads `PAYMENT_PROVIDERS_ENABLED` (as `enabledPaymentProviders`) and enforces the combinations (`fake` not in production; `ORDER_PAYMENT_TTL_MINUTES` at least 8 with a provider; in production an `https` `STOREFRONT_PUBLIC_URL`). Must NOT read `MONOBANK_TOKEN` (the provider package reads its own variables) and must NOT echo a value in any message.
- `src/payments-env.spec.ts` - unit tests of the payment variables: defaults, every combination, the production refusal of `fake`, the TTL floor, `https` in production, secrets never in messages.
- `src/config.spec.ts`, `src/storefront-env.spec.ts` - unit tests.

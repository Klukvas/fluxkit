# apps/storefront (Next.js App Router)

Narrative, rendering findings and how-tos: `apps/storefront/README.md`. Rules: `apps/storefront/AGENTS.md` (read the installed Next docs first).

## Root of the app
- `next.config.ts` - config as a function of the Next phase; redirects `/` to the default locale (literal, must match `defaultLocale` in `@fluxkit/ui`); rewrites `/store/:path*` to `${API_INTERNAL_URL}/store/:path*` in `next dev` ONLY (never in a build or `next start`; deployed environments use a reverse proxy, ADR 0026); `loadRootEnvFile` reads the root `.env` for `dev` and `start` (shell variables win); `headers()` returns the exported `headerRules`: the security headers on every path, built by `buildContentSecurityPolicy` and `securityHeaders` (CSP without nonces, `nosniff`, referrer policy, permissions policy, HSTS outside `next dev`), then `Referrer-Policy: no-referrer` on `TOKEN_PAGE_SOURCE` (`/:locale/order/:path*`, the guest order page; the last matching rule wins). `STOREFRONT_IMAGE_HOSTS` feeds `images.remotePatterns` (https, exact host names, no wildcard) and the CSP `img-src`: read by `next build` (the CSP is stored in the build output) and again by `next start` (the image optimizer), see README "Images". Must be ONE file: Next compiles only it for the config, a relative import of another TypeScript file fails. Must NOT contain page logic.
- `next.config.spec.ts`, `security-headers.spec.ts` - Vitest tests of the phase gating, the rewrite, the redirect, the `.env` loading, the headers (every directive, the production-only HSTS, the image-host validation, `no-referrer` on the order page and nowhere else, checked with Next's own path matcher) and the `images.remotePatterns` built from `STOREFRONT_IMAGE_HOSTS`.
- `postcss.config.mjs` - Tailwind v4 PostCSS plugin. `tsconfig.json` - the app's TypeScript settings (`tsc --noEmit` is `pnpm typecheck`).
- `next-env.d.ts` - generated by Next, committed so a clean clone type-checks. `next dev` rewrites it to point at `.next/dev/types`; do not commit that change (run `git checkout apps/storefront/next-env.d.ts`).

## `src/app` (routes compose; no logic)
- `globals.css` - imports Tailwind, design tokens and the token mapping; scans `packages/ui/src` for class names.
- `sitemap.ts`, `robots.ts` - `/sitemap.xml` (home, catalog, categories, products in both locales with hreflang links, `lastmod` = `publishedAt`; built by `lib/sitemap.server.ts`) and `/robots.txt` (`lib/robots.ts`). Per request (`connection()` through `publicOrigin()`), never at build.
- `[locale]/layout.tsx` - root layout: `<html lang data-theme>`, metadata from i18n, 404 for unknown locales, static params for the locales (nothing is prerendered: the shell reads the API per request), `SiteShell` around the page.
- `[locale]/(site)/layout.tsx` - the request-time locale check (storefront locales vs `GET /store/config`), nothing else. `(site)/loading.tsx` - client loading view. `(site)/page.tsx` - the home page: loads `getHomeData` and renders the sections of `layout/home.ts`; `generateMetadata` adds canonical and hreflang.
- `[locale]/(catalog)/layout.tsx` - re-exports the `(site)` locale check. A separate route group on purpose: NO `loading.tsx` above `catalog`, `c/[slug]` and `p/[slug]`, so `notFound()` answers a real 404 (`route-structure.spec.ts` enforces it). `(catalog)/catalog/page.tsx` - the product list (`?page`, `?brand`). `(catalog)/c/[slug]/page.tsx` - a category with its descendants' products, subcategory links, breadcrumbs and BreadcrumbList. `(catalog)/p/[slug]/page.tsx` - the product page: `ProductPurchase` island, description and specifications, Product and BreadcrumbList JSON-LD. Each has `generateMetadata` (title, description, canonical, hreflang, Open Graph, robots).
- `[locale]/(site)/cart/page.tsx` - the cart route: a shell that passes the shop's currency digits (`getShopExponent`) and the image host list to `CartPage`; metadata through `privateMetadata` (`noindex, nofollow`). `(site)/account/login/page.tsx`, `register/page.tsx` - shells that pass `?next` as it came to the form (the form checks it). `(site)/account/page.tsx`, `profile/page.tsx` - shells around the gated account pages. None of them reads the cart or the session on the server (the cookies have `Path=/store`) and none calls `notFound()`.
- `[locale]/(site)/checkout/page.tsx` - the checkout route: a shell that passes the shop's currency digits to `CheckoutPage`; `noindex, nofollow`. `(site)/order/[number]/page.tsx` - the guest order route: a shell that passes the number and the shop money to `GuestOrderPage`; a fixed title (never the number or anything of the fragment); `no-referrer` from `next.config.ts`; it reads no query, header or cookie. `(site)/account/orders/page.tsx`, `account/orders/[number]/page.tsx` - shells around the gated order history and order page (shop money from `getShopMoney`). None reads the cart, the session or the token on the server and none calls `notFound()`.
- `[locale]/error.tsx` (client, with reset), `[locale]/not-found.tsx` (client, through the I18n provider) - translated, token-styled states inside the shell.
- `[locale]/[...rest]/page.tsx` - any unmatched path under a locale: `notFound()`. Outside `(site)` on purpose, so the answer keeps a real 404 status.

## `src/components`
- `site-shell.tsx` - skip link, header, `<main id="main-content">`, footer inside the `I18nProvider`. `site-header.tsx` (server; category links, configured links, islands), `site-footer.tsx` (server), `home-sections.tsx` (section registry and the renderers: hero, category tiles, new products; data arrives from `loadHomeData`).
- Catalog (server components, props in, markup out): `product-card.tsx` (stretched title link, brand filter link, price or "from" price, availability badge, image through `StoreImage`), `product-grid.tsx` (labelled list, first four images eager), `catalog-view.tsx` (the catalog and category pages: breadcrumbs, `h1`, subcategories, brand filter chip, count, grid, empty states, `Pagination`), `product-details.tsx` (description as plain text, specifications as a definition list), `json-ld.tsx` (the ONLY `dangerouslySetInnerHTML`, fed by `serializeJsonLd`).
- Client islands: `product-purchase.tsx` (gallery, title, price, availability, option radio groups, quantity, add to cart through the cart store, `role="status"` live region; `ProductPurchaseView` is the testable part), `store-image.tsx` (`next/image` with a placeholder for a missing, disallowed or failing image), `cart-badge.tsx` (shows the shared cart store's item count; makes no request), `account-link.tsx` (shows the shared account store: sign in, the customer's first name as text, or the neutral link; makes no request), `locale-switcher.tsx` (same page in the other locale, query and fragment kept; the fragment is read from `location.hash` in an effect after each commit, so the server render never has it), `i18n-provider.tsx` (translator of the page locale from the client message subset). The `*View` components are pure and are what the tests render.
- Cart and accounts (client, step 6): `session-provider.tsx` (creates the store client and the cart and account stores once per page load; `useCart()`, `useAccount()` over `useSyncExternalStore`, `useStoreClient()` for the checkout and order islands; the ONLY place that creates a browser store client), `cart-page.tsx` (`CartPage` island, `CartPageView`, `CartLineView`, `QuantityFormView`), `session-notices.tsx` (the merge notices of a sign-in, rendered once at the top of `<main>`), `account-gate.tsx` (skeleton, page, sign-in redirect or retry; one `h1` in every state), `login-form.tsx` (also `AlreadySignedInView`), `register-form.tsx`, `account-overview.tsx` (details, links to the orders and the profile, sign out), `profile-forms.tsx` (profile and change password), `form-parts.tsx` (error summary, `TextField`), `use-form.ts` (values, failure, pending, double-submit ref, focus after a failed submit). Each has a pure `*View` that the tests render; `cart-page.spec.tsx`, `account.spec.tsx` cover markup, ARIA, `autocomplete`, notices, handlers (read from the element tree) and the real `uk`/`en` messages.
- Checkout and orders (client, step 7): `checkout-page.tsx` (`CheckoutPage` island: the checkout store over the shared cart store, form values in component state only, prefill from the account, `router.replace` to the outcome's link; `CheckoutPageView`: loading, error, empty, the form with the address only when the cart `requiresShipping`, the summary from the cart answer, the price-change OK and the new-total confirmation, the blocked reason, the neutral payment wording, the busy submit), `order-details.tsx` (`OrderDetailsView`: status text in a badge, payment wording with the expiry while `awaiting_payment`, items, the API's totals, contact, address, history, cancel with a confirmation step; `addressLines`), `guest-order-page.tsx` (`GuestOrderPage` island: reads `#t=` in an effect, looks up and cancels by POST, never renders the token on the server; `OrderStatusView`: loading, the one not-found state, error; `SaveLinkView` and `copyLink`: the private link in a read-only field with a Clipboard API copy and a visible fallback), `account-orders.tsx` (`AccountOrders` and `AccountOrder` islands behind the account gate; `AccountOrdersView`: list, pagination, empty, out of range, error). `checkout.spec.tsx`, `orders.spec.tsx` cover markup, ARIA, `autocomplete`, blocks, handlers, money from the API only, no hardcoded text and the server render of the guest page (no token).
- `status-views.tsx` - error, not-found and loading views (props in, markup out). `styles.ts` - shared class strings (tokens only).
- `test-helpers.ts` - sentinel translator and leftover-text helpers for the "no hardcoded text" tests. `shell.spec.tsx` - landmarks, skip link, islands, home outline, status views. `catalog.spec.tsx` - cards, grid, catalog view, filled home sections, the purchase island, product details, JSON-LD and `StoreImage` (markup, ARIA, no hardcoded text).

## `src/lib` (logic; no markup)
- `money.ts` - `formatMoney`, `minorUnitsToDecimalString`, `currencyExponent`: BigInt/string arithmetic, `Intl.NumberFormat` on the decimal string; never a float, never adds or multiplies money. `date.ts` - `formatDate`, `formatDateTime`.
- `problem-messages.ts` - maps problem `code`, `rule` and `errors[].code` to message keys (`errors.<code>`, `errors.rule.<rule>`, `errors.field.<code>`, `errors.generic`); never shows the API's `detail`. Spec compares the code list with `docs/api/openapi.json`.
- `store-data.ts` - `createStoreData` (catalog reads through `@fluxkit/api-client` with `?locale=`, no cookies, an 8 s `AbortSignal.timeout` on every read, `next: {revalidate: 60, tags}` or the caller's `revalidateSeconds` (the sitemap uses 3600) or `cache: "no-store"` for a list with a `brand` filter (`isCacheableProductQuery`: a free value must not create files in `.next/cache`), last-good fallback in memory, logs with the name and code of the cause, `StoreUnavailableError`) and `ensureLocalesSupported`. `store-data.server.ts` - the wired instance (`API_INTERNAL_URL` per request, `connection()` before any read): server code only. `navigation-categories.ts` - header categories, `null` on an outage.
- Catalog logic (pure, unit-tested): `variant-matcher.ts` (`findVariant`, `initialSelection`, `isValueAvailable`, `selectValue`, `selectedValueIds`: option and value CODES are data, a value of option N is available only if a variant has it with the choices before it, so the picker cannot dead-end), `catalog-query.ts` (page size 24, the API's offset cap, `parseCatalogQuery`, `catalogPath`, page-range rules), `catalog-data.ts` (what each route loads through `StoreData`: `loadHomeData`, `loadCatalogListing`, `loadProductPage`, `loadShopExponent`, `loadShopMoney`), `category-trail.ts` (breadcrumb trails), `attributes.ts` (specification rows from the API's definitions), `availability.ts` (status to message key and badge variant; add button rule), `product-media.ts` (gallery order and host check), `image-source.ts` (https host allow-list, no credentials or port), `add-to-cart.ts` (the 1 to 999 quantity limits), `cart-events.ts` (the cart-changed browser event).
- SEO: `seo.ts` (`absoluteUrl`, `languageAlternates`, `listingRobots`, `trimDescription`, `serializeJsonLd`, `productJsonLd`, `breadcrumbJsonLd`, `socialImageUrl`; prices are decimal strings from `minorUnitsToDecimalString`), `page-metadata.ts` (`homeMetadata`, `listingMetadata`, `productMetadata`), `sitemap.ts` (paging through the products, building the entries), `robots.ts`.
- Server wiring (server code only): `catalog-pages.server.ts` (React `cache` around the page loaders so a page and its `generateMetadata` share one load; `getShopExponent`, `getShopMoney`), `public-url.server.ts` (`publicOrigin`), `image-hosts.server.ts` (`imageHosts()` from the live environment), `sitemap.server.ts`. `test-fixtures.ts` - API-shaped sample data for tests (the only source file allowed to name options).
- `locale-check.ts` - `LocaleMismatchError`, `assertLocalesSupported`. `locale-path.ts` - `switchLocalePath` (keeps the query and a `#` fragment), `localizedHref` (plain storefront paths only). `client-messages.ts` - the message namespaces sent to the browser.
- Cart and accounts (step 6; pure TypeScript, no React, tested with injected clients): `cart-store.ts` (`createCartStore`, `cartReducer`: the cart as the browser knows it; reads and writes with `cache: "no-store"`; server values only; answers numbered by request order; every cart answer, also the cart of a `409 cart_changed` (`applyCart` for the checkout's), applied and published as `fluxkit:cart-changed`; failures keep the cart), `account-store.ts` (`createAccountStore`: session read, login, register, logout, profile, change password; one identical sign-in failure; `cartNotices` kept until dismissed; a second submit joins the request in flight; `sessionEnded` after a 401 elsewhere), `session-stores.ts` (wires a session change to a cart reload), `failure.ts` (`Failure` as message keys and field errors, `retryAfterSeconds`, `failureText`, `focusTarget`, `focusAfterFailure`, `missingRequired`), `safe-next.ts` (`safeNextPath`, `authHref`, `loginHref`, `currentPath`: same-locale storefront paths only; auth pages refused behind a trailing slash, encoding or dot segments), `cart-model.ts` (badge state, line flags, `checkoutBlock`, notice money), `cart-handlers.ts` (the cart page's callbacks, one store action each), `route-locale.ts` (locale narrowing for pages that cannot be "not found"), `test-fetch.ts` (staged fake `fetch` for out-of-order tests).
- Checkout and orders (step 7; pure TypeScript, no React, tested with injected clients, storage and crypto): `checkout-attempt.ts` (the attempt `{key, salt, requestHash}` in `sessionStorage`: `createAttemptManager`, `requestHash` = SHA-256 of the per-attempt salt and `canonicalJson` through `crypto.subtle`, `webAttemptCrypto` (throws `InsecureContextError`, no weak fallback), `sessionAttemptStorage` (probes, `null` when unusable); `checkoutOutcome`: the outcome table, keep or clear the key per answer), `checkout-form.ts` (values keyed by API field path, field order and ids, required fields, `buildCheckoutBody`: address only when the cart `requiresShipping`, blank optional fields left out, no billing or recipient fields, the expected total copied; `prefillFromCustomer`, `countryOptions` with `Intl.DisplayNames`), `checkout-store.ts` (`createCheckoutStore`: one request per submit, `checkoutBlock`, the expected total from the cart store at submit time, outcome side effects on the cart store, `prepare`, `confirmTotal`, `acknowledge`), `order-links.ts` (`guestOrderHref` with the token in the fragment only, `accountOrderHref`, `accountOrdersHref`, `tokenFromFragment`, `isOrderNumber`, `isAccessToken`), `order-model.ts` (statuses and their message keys, `canCancel`, `orderMoney`, `parseOrdersPage`, page size 24), `order-store.ts` (`createOrderStore` over a guest or account `OrderSource`: read, confirm, cancel, one not-found state, 401 ends the session; `createOrderListStore`).
- Timeouts and focus (step 10 review fixes): `request-timeout.ts` (`SERVER_READ_TIMEOUT_MS` 8 s, `BROWSER_READ_TIMEOUT_MS` 15 s, `BROWSER_WRITE_TIMEOUT_MS` 30 s, `withTimeout(fetch)` for the browser store client, `isTimeout`: a `TimeoutError` in the cause chain; `failure.ts` turns it into the retryable `errors.timeout`), `navigation-focus.ts` (`createNavigationFocus`: after a client-side navigation to another path the focus goes to the page's `h1`, else `main`; not on the first load) applied by `components/route-focus.tsx` (in the shell, renders nothing). `status-views.tsx` `NotFoundView` renders its own `<title>`.
- Focus along the order's cancel steps (step 8, found by the keyboard e2e scenario): `cancel-focus.ts` (`cancelFocusTarget(before, after)`: the safe answer when the question appears, back to the ask button when it closes, the success message when the order is cancelled; the element ids) with `cancel-focus.spec.ts`; the hook that applies it is `components/use-cancel-focus.ts`, used by the guest order page and the customer's order page.
- `src/client-boundary.spec.ts` - no `'use client'` file imports server-only wiring, `@fluxkit/config`, `@fluxkit/core` or `next/server`; nothing imports `@fluxkit/core`; every message key a client file writes out is in a serialized namespace; only the session provider creates a browser store client and the header islands read nothing themselves. `src/route-structure.spec.ts` - no `loading.tsx` above a route that can be not found. `src/source-guards.spec.ts` - `dangerouslySetInnerHTML` only in `json-ld.tsx`, no niche-specific option names, no float money math, `next/image` only in `store-image.tsx`; no browser storage, `document.cookie` or logged password in the cart and account code; `router.push/replace` only with `safeNextPath`, `localizedHref` or the gate's login link; the merge notices are rendered in one place; `sessionStorage` only through `sessionAttemptStorage` in the checkout island, no `localStorage`, `indexedDB` or `document.cookie` anywhere, no `document.title`; `location.hash` read only by the guest order page and the locale switcher, inside effects; `lookupOrder`/`cancelOrder` called only by `order-store.ts`; the order route shell reads nothing that could carry the token; no console call in the checkout and order code mentions a token, link, body or contact field; `router.replace` also accepts `result.href` (the checkout outcome's link).

## `e2e` (Playwright, step 8; run with `pnpm test:e2e`, NOT part of `pnpm test`; details and troubleshooting: `e2e/README.md`)
- `playwright.config.ts` - Chromium only, one worker, `*.e2e.ts` under `e2e/tests`; starts the built API, the built storefront and the proxy as `webServer` entries (never reuses a running server); retries 0 locally and 1 in CI; trace on first retry, screenshot and video on failure.
- `proxy.ts` - the same-origin reverse proxy (node:http, no dependency, erasable TypeScript run by `node --experimental-strip-types`): `/store/*` and `/admin/*` to the API, the rest to the storefront, sets `X-Forwarded-For` itself; turns the TEST-ONLY header `x-e2e-client` into a per-test client address so no rate limit couples tests. Must NOT be used outside the suite.
- `prepare-database.ts` - wipes a `*_e2e_test` database (refuses any other name), then runs the API's built migrate, seed and create-admin commands. Must NOT touch any other database.
- `support/env.ts` - ports, the throwaway owner, `requireE2eDatabaseUrl`, `apiEnvironment` (every behavioural variable of the API process is set here), `clientMarker`. `support/api.ts` - `StoreApi` (cart, checkout, register through the API with the cookie jar of a browser context or of another shopper) and `AdminApi` (sign-in, price, stock; used only to change the catalog behind a shopper's back). `support/fixtures.ts` - the `test` object: per-test client marker on every request, `shopper`, `otherShopper`, `admin`, `uniqueEmail`. `support/flows.ts` - form filling, option choice, token and order number readers, `tabTo` (keyboard navigation), `waitForHydration`, `uah`.
- `tests/*.e2e.ts` - the scenarios: `guest-purchase`, `customer-account`, `cart-changes`, `locale-switch`, `keyboard-checkout`, `token-hygiene`, `double-submit` (holds the first answer so a second request would show), `failed-sign-in`, `not-found` (with the title), and from the step 10 review `pre-hydration-forms` (JavaScript off, scripts held back: no password or personal data in a URL or `Referer`), `account-gate` (the query string kept in `next`) and `navigation-focus`. They assert what a user sees; they never import from `src`.
- `vitest.config.ts` (storefront root) - excludes `e2e/**` from the unit run.

## Configuration (internal, not a public contract in v1)
- `src/layout/home.ts` - the home sections in order with props (`categoryTiles {limit}`, `newProducts {limit}`). `src/layout/navigation.ts` - header and footer links (message keys, locale-less paths), `MAIN_CONTENT_ID`, the session link targets. `src/config/checkout.ts` - allowed shipping countries, default country `UA`, address fields shown and required (read by `lib/checkout-form.ts`). `layout/layout-config.spec.ts` checks keys, paths and defaults.

## `src/messages`
- `uk.json`, `en.json` - every user-facing string; `index.ts` maps locale to messages; `messages.spec.ts` - same keys, same `{placeholders}`, complete plural forms (uk one/few/many/other, en one/other), and every key-like literal in the source exists.

Run: `pnpm --filter @fluxkit/storefront dev -p 3001` (needs `pnpm build` once so workspace packages are built, and `API_INTERNAL_URL` in the root `.env` or the shell; the API on port 3000 with `STORE_COOKIE_SECURE=false`). Next telemetry is disabled in the scripts.

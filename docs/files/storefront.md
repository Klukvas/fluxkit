# apps/storefront (Next.js App Router)

Narrative, rendering findings and how-tos: `apps/storefront/README.md`. Rules: `apps/storefront/AGENTS.md` (read the installed Next docs first).

## Root of the app
- `next.config.ts` - config as a function of the Next phase; redirects `/` to the default locale (literal, must match `defaultLocale` in `@fluxkit/ui`); rewrites `/store/:path*` to `${API_INTERNAL_URL}/store/:path*` and `/media/:path*` to `${API_INTERNAL_URL}/media/:path*` in `next dev` ONLY, and in `next dev` only sets `env.FLUXKIT_DEV_MEDIA_BASE_URL` (`MEDIA_PUBLIC_BASE_URL`, else `API_INTERNAL_URL` + `/media`; owner decision 2026-11-01, local demo images) (never in a build or `next start`; deployed environments use a reverse proxy, ADR 0026); `loadRootEnvFile` reads the root `.env` for `dev` and `start` (shell variables win); `headers()` returns the exported `headerRules`: the security headers on every path, built by `buildContentSecurityPolicy` and `securityHeaders` (CSP without nonces, `nosniff`, referrer policy, permissions policy, HSTS outside `next dev`), then `Referrer-Policy: no-referrer` on `TOKEN_PAGE_SOURCE` (`/:locale/order/:path*`, the guest order page), the emailed-link pages and `PAYMENT_RETURN_PAGE_SOURCE` (`/:locale/payment/return`; the last matching rule wins). `STOREFRONT_IMAGE_HOSTS` feeds `images.remotePatterns` (https, exact host names, no wildcard) and the CSP `img-src`: read by `next build` (the CSP is stored in the build output) and again by `next start` (the image optimizer), see README "Images". Must be ONE file: Next compiles only it for the config, a relative import of another TypeScript file fails. Must NOT contain page logic.
- `next.config.ts` also holds `assertNoLegalPlaceholders` (the opt-in release check `STOREFRONT_REQUIRE_LEGAL_TEXT=true`: a production build refuses while a `legal.*` message of the MERGED messages (`readMergedMessages`: the area files `src/messages/<locale>/*.json`, then `src/messages-extra/<locale>.json`, then `src/messages-overrides/<locale>.json`, in plain Node; fails closed on no files, a leftover flat `*.json`, a key in two files, a missing extras or overrides file, an extra key outside `custom.` (`CUSTOM_MESSAGE_NAMESPACE`, kept equal to `areas.ts` by a spec) or already in the base, an unknown override key or an extra or override value that is not a non-empty string; a spec keeps it equal to `messagesByLocale`) carries the placeholder marker or a value of `src/config/legal-identity.json` is unset or blank, or (repair batch 2) `src/config/demo-content.json` still lists demo copy, read by `demoContentLeft`; fails closed) and the marker constant, kept equal to `src/config/legal.ts` by a spec.
- `next.config.spec.ts`, `security-headers.spec.ts` - Vitest tests of the phase gating, the rewrite, the redirect, the `.env` loading, the headers (every directive, the production-only HSTS, the image-host validation, `no-referrer` on the order page and nowhere else, checked with Next's own path matcher) and the `images.remotePatterns` built from `STOREFRONT_IMAGE_HOSTS`.
- `postcss.config.mjs` - Tailwind v4 PostCSS plugin. `tsconfig.json` - the app's TypeScript settings (`tsc --noEmit` is `pnpm typecheck`).
- `next-env.d.ts` - generated by Next, committed so a clean clone type-checks. `next dev` rewrites it to point at `.next/dev/types`; do not commit that change (run `git checkout apps/storefront/next-env.d.ts`).

## `src/app` (routes compose; no logic)
- `globals.css` - imports Tailwind, design tokens, the token mapping and, last, the fork-owned `@fluxkit/theme/brand-overrides.css` (2026-11-10; never `admin-overrides.css`, `packages/theme/src/brand-overrides.spec.ts`); scans `packages/ui/src` for class names; the header's single token classes (`.fk-menu-item`, `.fk-nav-link`, `.fk-header-button`, `.fk-menu-panel`, `.fk-icon`, `.fk-header-row`, `.fk-header-nav`, `.fk-header-end`, `.fk-header-slot`, `.fk-chevron`, `.fk-suggest-list`, `.fk-site-footer`, through `@apply`: smaller first HTML; since ADR 0048 only a loose cap in `shell.spec.tsx`) and the decorative flags (`.fk-flag`, `.fk-flag-<country>`).
- `sitemap.ts`, `robots.ts` - `/sitemap.xml` (home, catalog, categories, products in both locales with hreflang links, `lastmod` = `publishedAt`; built by `lib/sitemap.server.ts`) and `/robots.txt` (`lib/robots.ts`). Per request (`connection()` through `publicOrigin()`), never at build.
- `[locale]/layout.tsx` - root layout: `<html lang data-theme>` (plus the `variable` classes of `config/fonts.ts`, none upstream) (the theme from the `fluxkit_theme` cookie or `config/theme.ts`, read with `cookies()`: the only cookie read of the storefront; ADR 0045), metadata from i18n (plus the icon links of `config/brand.ts`, none upstream), `generateViewport` (`theme-color` of `config/brand.ts` for the cookie's theme; nothing read and nothing rendered upstream), 404 for unknown locales, static params for the locales (nothing is prerendered: the shell reads the API per request), `SiteShell` around the page.
- `[locale]/(site)/layout.tsx` - the request-time locale check (storefront locales vs `GET /store/config`), nothing else. `(site)/(home)/loading.tsx` - client loading view, the ONLY `loading.tsx` of the app (ADR 0048: every other page renders inside the shell, so it is in the first HTML; `route-structure.spec.ts`). `(site)/(home)/page.tsx` - the home page (a nested route group, URL `/{locale}`): renders the sections of `config/home.ts` through `HomeSections`, each data section loaded by `getHomeSection` (started together, streamed one by one; the admin's banners are awaited, not streamed); `generateMetadata` adds canonical and hreflang.
- `theme/route.ts` - `POST /theme`: the theme switch without a script (`lib/theme-route.ts`; `403` for a form from another site or origin than `STOREFRONT_PUBLIC_URL`); outside `[locale]`, no page.
- `[locale]/(catalog)/layout.tsx` - re-exports the `(site)` locale check. A separate route group on purpose: NO `loading.tsx` above `catalog`, `c/[slug]` and `p/[slug]`, so `notFound()` answers a real 404 (`route-structure.spec.ts` enforces it). `(catalog)/catalog/page.tsx` - the product list (`?page`, `?brand`). `(catalog)/c/[slug]/page.tsx` - a category with its descendants' products, subcategory links, breadcrumbs and BreadcrumbList. `(catalog)/p/[slug]/page.tsx` - the product page: `ProductPurchase` island, description and specifications, Product and BreadcrumbList JSON-LD. Each has `generateMetadata` (title, description, canonical, hreflang, Open Graph, robots).
- `[locale]/(site)/cart/page.tsx` - the cart route: a shell that passes the shop's currency digits (`getShopExponent`) and the image host list to `CartPage`; metadata through `privateMetadata` (`noindex, nofollow`). `(site)/account/login/page.tsx`, `register/page.tsx` - shells that pass `?next` as it came to the form (the form checks it). `(site)/account/page.tsx`, `profile/page.tsx` - shells around the gated account pages (the overview shell passes `emailDelivery`). `(site)/account/forgot-password/page.tsx`, `reset-password/page.tsx`, `verify-email/page.tsx` - shells of the emailed-link pages (email plan step 10): a fixed title, `privateMetadata(..., { noReferrer: true })`, `emailDelivery` from `getEmailDelivery()`; they read no query, header, cookie or token (the token is in the fragment, unknown to the server). `login/page.tsx` also passes `emailDelivery` to the form. None of them reads the cart or the session on the server (the cookies have `Path=/store`) and none calls `notFound()`.
- `[locale]/(site)/checkout/page.tsx` - the checkout route: a shell that passes the shop's currency digits to `CheckoutPage`; `noindex, nofollow`. `(site)/order/[number]/page.tsx` - the guest order route: a shell that passes the number and the shop money to `GuestOrderPage`; a fixed title (never the number or anything of the fragment); `no-referrer` from `next.config.ts`; it reads no query, header or cookie. `(site)/account/orders/page.tsx`, `account/orders/[number]/page.tsx` - shells around the gated order history and order page (shop money from `getShopMoney`). None reads the cart, the session or the token on the server and none calls `notFound()`.
- `[locale]/error.tsx` (client, with reset), `[locale]/not-found.tsx` (client, through the I18n provider) - translated, token-styled states inside the shell.
- `[locale]/[...rest]/page.tsx` - any unmatched path under a locale: `notFound()`. Outside `(site)` on purpose, so the answer keeps a real 404 status.
- `[locale]/(pages)/layout.tsx` - re-exports the `(site)` locale check; its own group with NO `loading.tsx`, like `(catalog)`. `(pages)/[page]/page.tsx` - `/{locale}/<slug>`: a shop page of `config/shop-pages.ts` (`findShopPage`; an unknown or switched-off slug is a real 404), metadata from `shopPageMetadata`, BreadcrumbList JSON-LD. Must NOT read the API or the request (static content). Static routes (`cart`, `catalog`, ...) win over this segment.

## `src/lib` (logic; no markup)
- `money.ts` - `formatMoney`, `minorUnitsToDecimalString`, `currencyExponent`: BigInt/string arithmetic and a fixed per-locale table of separators and currency symbols (the same text on the server and in the browser; must NOT display `Intl.NumberFormat` output, whose ICU data differs); never a float, never adds or multiplies money. `date.ts` - `formatDate`, `formatDateTime`.
- `problem-messages.ts` - maps problem `code`, `rule` and `errors[].code` to message keys (`errors.<code>`, `errors.rule.<rule>`, `errors.field.<code>`, `errors.generic`); never shows the API's `detail`. Spec compares the code list with `docs/api/openapi.json`.

# apps/storefront (Next.js App Router)

Narrative, rendering findings and how-tos: `apps/storefront/README.md`. Rules: `apps/storefront/AGENTS.md` (read the installed Next docs first).

## Root of the app
- `next.config.ts` - config as a function of the Next phase; redirects `/` to the default locale (literal, must match `defaultLocale` in `@fluxkit/ui`); rewrites `/store/:path*` to `${API_INTERNAL_URL}/store/:path*` in `next dev` ONLY (never in a build or `next start`; deployed environments use a reverse proxy, ADR 0026); `loadRootEnvFile` reads the root `.env` for `dev` and `start` (shell variables win); `headers()` returns the exported `headerRules`: the security headers on every path, built by `buildContentSecurityPolicy` and `securityHeaders` (CSP without nonces, `nosniff`, referrer policy, permissions policy, HSTS outside `next dev`), then `Referrer-Policy: no-referrer` on `TOKEN_PAGE_SOURCE` (`/:locale/order/:path*`, the guest order page), the emailed-link pages and `PAYMENT_RETURN_PAGE_SOURCE` (`/:locale/payment/return`; the last matching rule wins). `STOREFRONT_IMAGE_HOSTS` feeds `images.remotePatterns` (https, exact host names, no wildcard) and the CSP `img-src`: read by `next build` (the CSP is stored in the build output) and again by `next start` (the image optimizer), see README "Images". Must be ONE file: Next compiles only it for the config, a relative import of another TypeScript file fails. Must NOT contain page logic.
- `next.config.ts` also holds `assertNoLegalPlaceholders` (the opt-in release check `STOREFRONT_REQUIRE_LEGAL_TEXT=true`: a production build refuses while a `legal.*` message carries the placeholder marker; fails closed) and the marker constant, kept equal to `src/config/legal.ts` by a spec.
- `next.config.spec.ts`, `security-headers.spec.ts` - Vitest tests of the phase gating, the rewrite, the redirect, the `.env` loading, the headers (every directive, the production-only HSTS, the image-host validation, `no-referrer` on the order page and nowhere else, checked with Next's own path matcher) and the `images.remotePatterns` built from `STOREFRONT_IMAGE_HOSTS`.
- `postcss.config.mjs` - Tailwind v4 PostCSS plugin. `tsconfig.json` - the app's TypeScript settings (`tsc --noEmit` is `pnpm typecheck`).
- `next-env.d.ts` - generated by Next, committed so a clean clone type-checks. `next dev` rewrites it to point at `.next/dev/types`; do not commit that change (run `git checkout apps/storefront/next-env.d.ts`).

## `src/app` (routes compose; no logic)
- `globals.css` - imports Tailwind, design tokens and the token mapping; scans `packages/ui/src` for class names.
- `sitemap.ts`, `robots.ts` - `/sitemap.xml` (home, catalog, categories, products in both locales with hreflang links, `lastmod` = `publishedAt`; built by `lib/sitemap.server.ts`) and `/robots.txt` (`lib/robots.ts`). Per request (`connection()` through `publicOrigin()`), never at build.
- `[locale]/layout.tsx` - root layout: `<html lang data-theme>`, metadata from i18n, 404 for unknown locales, static params for the locales (nothing is prerendered: the shell reads the API per request), `SiteShell` around the page.
- `[locale]/(site)/layout.tsx` - the request-time locale check (storefront locales vs `GET /store/config`), nothing else. `(site)/loading.tsx` - client loading view. `(site)/page.tsx` - the home page: loads `getHomeData` and renders the sections of `layout/home.ts`; `generateMetadata` adds canonical and hreflang.
- `[locale]/(catalog)/layout.tsx` - re-exports the `(site)` locale check. A separate route group on purpose: NO `loading.tsx` above `catalog`, `c/[slug]` and `p/[slug]`, so `notFound()` answers a real 404 (`route-structure.spec.ts` enforces it). `(catalog)/catalog/page.tsx` - the product list (`?page`, `?brand`). `(catalog)/c/[slug]/page.tsx` - a category with its descendants' products, subcategory links, breadcrumbs and BreadcrumbList. `(catalog)/p/[slug]/page.tsx` - the product page: `ProductPurchase` island, description and specifications, Product and BreadcrumbList JSON-LD. Each has `generateMetadata` (title, description, canonical, hreflang, Open Graph, robots).
- `[locale]/(site)/cart/page.tsx` - the cart route: a shell that passes the shop's currency digits (`getShopExponent`) and the image host list to `CartPage`; metadata through `privateMetadata` (`noindex, nofollow`). `(site)/account/login/page.tsx`, `register/page.tsx` - shells that pass `?next` as it came to the form (the form checks it). `(site)/account/page.tsx`, `profile/page.tsx` - shells around the gated account pages (the overview shell passes `emailDelivery`). `(site)/account/forgot-password/page.tsx`, `reset-password/page.tsx`, `verify-email/page.tsx` - shells of the emailed-link pages (email plan step 10): a fixed title, `privateMetadata(..., { noReferrer: true })`, `emailDelivery` from `getEmailDelivery()`; they read no query, header, cookie or token (the token is in the fragment, unknown to the server). `login/page.tsx` also passes `emailDelivery` to the form. None of them reads the cart or the session on the server (the cookies have `Path=/store`) and none calls `notFound()`.
- `[locale]/(site)/checkout/page.tsx` - the checkout route: a shell that passes the shop's currency digits to `CheckoutPage`; `noindex, nofollow`. `(site)/order/[number]/page.tsx` - the guest order route: a shell that passes the number and the shop money to `GuestOrderPage`; a fixed title (never the number or anything of the fragment); `no-referrer` from `next.config.ts`; it reads no query, header or cookie. `(site)/account/orders/page.tsx`, `account/orders/[number]/page.tsx` - shells around the gated order history and order page (shop money from `getShopMoney`). None reads the cart, the session or the token on the server and none calls `notFound()`.
- `[locale]/error.tsx` (client, with reset), `[locale]/not-found.tsx` (client, through the I18n provider) - translated, token-styled states inside the shell.
- `[locale]/[...rest]/page.tsx` - any unmatched path under a locale: `notFound()`. Outside `(site)` on purpose, so the answer keeps a real 404 status.

## `e2e` (Playwright, step 8; run with `pnpm test:e2e`, NOT part of `pnpm test`; details and troubleshooting: `e2e/README.md`)
- `playwright.config.ts` - Chromium only, one worker, `*.e2e.ts` under `e2e/tests`; starts the built API, the built storefront and the proxy as `webServer` entries (never reuses a running server); retries 0 locally and 1 in CI; trace on first retry, screenshot and video on failure.
- `proxy.ts` - the same-origin reverse proxy (node:http, no dependency, erasable TypeScript run by `node --experimental-strip-types`): `/store/*`, `/admin/*`, `/media/*` and `/webhooks/payments/*` (the payment provider's notifications, bytes unchanged) to the API (answers passed back unchanged, no cookie added), the rest to the storefront, sets `X-Forwarded-For` itself; turns the TEST-ONLY header `x-e2e-client` into a per-test client address so no rate limit couples tests. Must NOT be used outside the suite.
- `prepare-database.ts` - wipes a `*_e2e_test` database (refuses any other name), then runs the API's built migrate, seed and create-admin commands, and wipes and creates the temp upload directory `E2E_MEDIA_DIR`; with search on it first creates the suite's scoped engine key and, after the seed, runs the built `search/reindex.js` (`pnpm search:reindex`). Must NOT touch any other database or directory. `global-teardown.ts` - removes that directory and, with search on, the suite's engine key and indexes. `support/meili.ts` - the engine side of the setup: removes leftovers of an earlier run by the suite's prefix and key description, creates the scoped key with the master key, removes both again.
- `support/env.ts` (`PAYMENT_PROVIDERS_ENABLED=fake` since payments plan step 9; `SEARCH_ENABLED` and `MEILI_INDEX_PREFIX` since search plan step 10a, `E2E_SEARCH=off` turns search off) - ports, the throwaway owner, `requireE2eDatabaseUrl`, `apiEnvironment` (every behavioural variable of the API process is set here, the `MEDIA_*` ones included), `E2E_MEDIA_DIR`, `E2E_MAIL_FILE`, `clientMarker`. `support/mailbox.ts` - reads the fake email provider's capture file (`FAKE_EMAIL_CAPTURE_FILE`): `readMailbox`, `newestLink` (waits for the newest reset or verification link to an address), `linksTo`, `inLocale`. `support/api.ts` - `StoreApi` (cart, checkout, register through the API with the cookie jar of a browser context or of another shopper) and `AdminApi` (sign-in, price, stock, shipping methods, mark paid and create a waybill of the fake provider; used only to change the catalog or the shop behind a shopper's back). `support/fixtures.ts` - the `test` object: per-test client marker on every request, `shopper`, `otherShopper`, `admin`, `uniqueEmail`. `support/flows.ts` - form filling (`fillContactDetails`, `fillCheckoutForm`), `rowValue` (the value next to a `<dt>`), option choice, token and order number readers, `tabTo` (keyboard navigation), `waitForHydration`, `uah`.
- `tests/*.e2e.ts` - the scenarios: `guest-purchase`, `customer-account`, `cart-changes`, `locale-switch`, `keyboard-checkout`, `token-hygiene`, `double-submit` (holds the first answer so a second request would show), `shipping-checkout` (shipping plan step 10: a flat courier, a pickup point of the fake provider chosen with the keyboard and its tracking, a free store pickup, a delivery price changed behind the shopper's back; the API of the suite runs with `SHIPPING_PROVIDERS_ENABLED=fake`, each test creates its own methods and deactivates them), `failed-sign-in`, `not-found` (with the title), and from the step 10 review `pre-hydration-forms` (JavaScript off, scripts held back: no password or personal data in a URL or `Referer`), `account-gate` (the query string kept in `next`) and `navigation-focus`, `account-email` (email plan step 10: forgot -> captured mail -> reset -> sign in, the neutral answer, invalid links, verification, token hygiene; the API of the suite runs with `EMAIL_PROVIDER=fake`, `support/mailbox.ts` reads the captured mail), and `payment-webhook` (payments plan step 11: the test plays the payment provider and POSTs the fake's signed webhook to the real route through the proxy (`support/fake-provider.ts`): a paid order and the return page turning to paid, a replay, forged / unsigned / altered / oversized bodies refused, amount mismatches flagged, a late payment after a cancel with its queued refund), and `payment` (payments plan step 9: the pay step, the redirect to the provider's page (answered by a Playwright stub), the return page on the real status route, nothing in the query trusted, no hand-off on another device, a customer's order, keyboard and focus, and browser-level stubs for the states the fake provider cannot produce; see `e2e/README.md`), `media-route` (step 8 of the media plan: `/media/*` reaches the API through the proxy, and a product with an uploaded image renders its page with the placeholder). `search` (search plan step 10a: the header box with suggestions by keyboard, aborted stale requests, the results page with facets, sort, price, chips, focus, no-script forms, 404s, escaping, and the per-address window through the Next server) and `search-off` (runs only with `E2E_SEARCH=off`: no box, a 404 page, the catalog still works). They assert what a user sees; they never import from `src`.
- `vitest.config.ts` (storefront root) - excludes `e2e/**` from the unit run.

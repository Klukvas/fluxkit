# apps/storefront (Next.js App Router)

Narrative, rendering findings and how-tos: `apps/storefront/README.md`. Rules: `apps/storefront/AGENTS.md` (read the installed Next docs first).

## Root of the app
- `next.config.ts` - config as a function of the Next phase; redirects `/` to the default locale (literal, must match `defaultLocale` in `@fluxkit/ui`); rewrites `/store/:path*` to `${API_INTERNAL_URL}/store/:path*` in `next dev` ONLY (never in a build or `next start`; deployed environments use a reverse proxy, ADR 0026); `loadRootEnvFile` reads the root `.env` for `dev` and `start` (shell variables win); `headers()` applies the security headers to every path, built by the exported `buildContentSecurityPolicy` and `securityHeaders` (CSP without nonces, `nosniff`, referrer policy, permissions policy, HSTS outside `next dev`). `STOREFRONT_IMAGE_HOSTS` is read at build time (Next stores `headers()` in the routes manifest). Must be ONE file: Next compiles only it for the config, a relative import of another TypeScript file fails. Must NOT contain page logic.
- `next.config.spec.ts`, `security-headers.spec.ts` - Vitest tests of the phase gating, the rewrite, the redirect, the `.env` loading and the headers (every directive, the production-only HSTS, the image-host validation).
- `postcss.config.mjs` - Tailwind v4 PostCSS plugin.
- `next-env.d.ts` - generated by Next, committed so a clean clone type-checks. `next dev` rewrites it to point at `.next/dev/types`; do not commit that change (run `git checkout apps/storefront/next-env.d.ts`).

## `src/app` (routes compose; no logic)
- `globals.css` - imports Tailwind, design tokens and the token mapping; scans `packages/ui/src` for class names.
- `[locale]/layout.tsx` - root layout: `<html lang data-theme>`, metadata from i18n, 404 for unknown locales, static params for the locales (nothing is prerendered: the shell reads the API per request), `SiteShell` around the page.
- `[locale]/(site)/layout.tsx` - the request-time locale check (storefront locales vs `GET /store/config`), nothing else. `(site)/loading.tsx` - client loading view. `(site)/page.tsx` - the home page: the sections of `layout/home.ts`.
- `[locale]/error.tsx` (client, with reset), `[locale]/not-found.tsx` (client, through the I18n provider) - translated, token-styled states inside the shell.
- `[locale]/[...rest]/page.tsx` - any unmatched path under a locale: `notFound()`. Outside `(site)` on purpose, so the answer keeps a real 404 status.

## `src/components`
- `site-shell.tsx` - skip link, header, `<main id="main-content">`, footer inside the `I18nProvider`. `site-header.tsx` (server; category links, configured links, islands), `site-footer.tsx` (server), `home-sections.tsx` (section registry and the renderers).
- Client islands: `cart-badge.tsx` (`GET /store/cart` once per page load), `account-link.tsx` (`GET /store/account/me`, 401 = guest), `locale-switcher.tsx` (same page in the other locale, query kept), `i18n-provider.tsx` (translator of the page locale from the client message subset). The `*View` components are pure and are what the tests render.
- `status-views.tsx` - error, not-found and loading views (props in, markup out). `styles.ts` - shared class strings (tokens only).
- `test-helpers.ts` - sentinel translator and leftover-text helpers for the "no hardcoded text" tests. `shell.spec.tsx` - landmarks, skip link, islands, home outline, status views.

## `src/lib` (logic; no markup)
- `money.ts` - `formatMoney`, `minorUnitsToDecimalString`, `currencyExponent`: BigInt/string arithmetic, `Intl.NumberFormat` on the decimal string; never a float, never adds or multiplies money. `date.ts` - `formatDate`, `formatDateTime`.
- `problem-messages.ts` - maps problem `code`, `rule` and `errors[].code` to message keys (`errors.<code>`, `errors.rule.<rule>`, `errors.field.<code>`, `errors.generic`); never shows the API's `detail`. Spec compares the code list with `docs/api/openapi.json`.
- `store-data.ts` - `createStoreData` (catalog reads through `@fluxkit/api-client` with `?locale=`, no cookies, `next: {revalidate: 60, tags}`, last-good fallback in memory, `StoreUnavailableError`) and `ensureLocalesSupported`. `store-data.server.ts` - the wired instance (`API_INTERNAL_URL` per request, `connection()` before any read): server code only. `navigation-categories.ts` - header categories, `null` on an outage.
- `locale-check.ts` - `LocaleMismatchError`, `assertLocalesSupported`. `locale-path.ts` - `switchLocalePath`, `localizedHref` (plain storefront paths only). `session-state.ts` - the cart badge and account link loaders (browser, `no-store`). `client-messages.ts` - the message namespaces sent to the browser.
- `client-boundary.spec.ts` (in `src/`) - no `'use client'` file imports server-only wiring, `@fluxkit/config`, `@fluxkit/core` or `next/server`; nothing imports `@fluxkit/core`.

## Configuration (internal, not a public contract in v1)
- `src/layout/home.ts` - the home sections in order with props. `src/layout/navigation.ts` - header and footer links (message keys, locale-less paths), `MAIN_CONTENT_ID`, the session link targets. `src/config/checkout.ts` - allowed shipping countries, default country `UA`, address fields shown (consumed by step 7). `layout/layout-config.spec.ts` checks keys, paths and defaults.

## `src/messages`
- `uk.json`, `en.json` - every user-facing string; `index.ts` maps locale to messages; `messages.spec.ts` - same keys, same `{placeholders}`, complete plural forms (uk one/few/many/other, en one/other), and every key-like literal in the source exists.

Run: `pnpm --filter @fluxkit/storefront dev -p 3001` (needs `pnpm build` once so workspace packages are built, and `API_INTERNAL_URL` in the root `.env` or the shell; the API on port 3000 with `STORE_COOKIE_SECURE=false`). Next telemetry is disabled in the scripts.

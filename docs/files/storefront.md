# apps/storefront (Next.js App Router)

Narrative, rendering findings and how-tos: `apps/storefront/README.md`. Rules: `apps/storefront/AGENTS.md` (read the installed Next docs first).

## Root of the app
- `next.config.ts` - config as a function of the Next phase; redirects `/` to the default locale (literal, must match `defaultLocale` in `@fluxkit/ui`); rewrites `/store/:path*` to `${API_INTERNAL_URL}/store/:path*` in `next dev` ONLY (never in a build or `next start`; deployed environments use a reverse proxy, ADR 0026); `loadRootEnvFile` reads the root `.env` for `dev` and `start` (shell variables win); `headers()` applies the security headers to every path, built by the exported `buildContentSecurityPolicy` and `securityHeaders` (CSP without nonces, `nosniff`, referrer policy, permissions policy, HSTS outside `next dev`). `STOREFRONT_IMAGE_HOSTS` feeds `images.remotePatterns` (https, exact host names, no wildcard) and the CSP `img-src`: read by `next build` (the CSP is stored in the build output) and again by `next start` (the image optimizer), see README "Images". Must be ONE file: Next compiles only it for the config, a relative import of another TypeScript file fails. Must NOT contain page logic.
- `next.config.spec.ts`, `security-headers.spec.ts` - Vitest tests of the phase gating, the rewrite, the redirect, the `.env` loading, the headers (every directive, the production-only HSTS, the image-host validation) and the `images.remotePatterns` built from `STOREFRONT_IMAGE_HOSTS`.
- `postcss.config.mjs` - Tailwind v4 PostCSS plugin.
- `next-env.d.ts` - generated by Next, committed so a clean clone type-checks. `next dev` rewrites it to point at `.next/dev/types`; do not commit that change (run `git checkout apps/storefront/next-env.d.ts`).

## `src/app` (routes compose; no logic)
- `globals.css` - imports Tailwind, design tokens and the token mapping; scans `packages/ui/src` for class names.
- `sitemap.ts`, `robots.ts` - `/sitemap.xml` (home, catalog, categories, products in both locales with hreflang links, `lastmod` = `publishedAt`; built by `lib/sitemap.server.ts`) and `/robots.txt` (`lib/robots.ts`). Per request (`connection()` through `publicOrigin()`), never at build.
- `[locale]/layout.tsx` - root layout: `<html lang data-theme>`, metadata from i18n, 404 for unknown locales, static params for the locales (nothing is prerendered: the shell reads the API per request), `SiteShell` around the page.
- `[locale]/(site)/layout.tsx` - the request-time locale check (storefront locales vs `GET /store/config`), nothing else. `(site)/loading.tsx` - client loading view. `(site)/page.tsx` - the home page: loads `getHomeData` and renders the sections of `layout/home.ts`; `generateMetadata` adds canonical and hreflang.
- `[locale]/(catalog)/layout.tsx` - re-exports the `(site)` locale check. A separate route group on purpose: NO `loading.tsx` above `catalog`, `c/[slug]` and `p/[slug]`, so `notFound()` answers a real 404 (`route-structure.spec.ts` enforces it). `(catalog)/catalog/page.tsx` - the product list (`?page`, `?brand`). `(catalog)/c/[slug]/page.tsx` - a category with its descendants' products, subcategory links, breadcrumbs and BreadcrumbList. `(catalog)/p/[slug]/page.tsx` - the product page: `ProductPurchase` island, description and specifications, Product and BreadcrumbList JSON-LD. Each has `generateMetadata` (title, description, canonical, hreflang, Open Graph, robots).
- `[locale]/error.tsx` (client, with reset), `[locale]/not-found.tsx` (client, through the I18n provider) - translated, token-styled states inside the shell.
- `[locale]/[...rest]/page.tsx` - any unmatched path under a locale: `notFound()`. Outside `(site)` on purpose, so the answer keeps a real 404 status.

## `src/components`
- `site-shell.tsx` - skip link, header, `<main id="main-content">`, footer inside the `I18nProvider`. `site-header.tsx` (server; category links, configured links, islands), `site-footer.tsx` (server), `home-sections.tsx` (section registry and the renderers: hero, category tiles, new products; data arrives from `loadHomeData`).
- Catalog (server components, props in, markup out): `product-card.tsx` (stretched title link, brand filter link, price or "from" price, availability badge, image through `StoreImage`), `product-grid.tsx` (labelled list, first four images eager), `catalog-view.tsx` (the catalog and category pages: breadcrumbs, `h1`, subcategories, brand filter chip, count, grid, empty states, `Pagination`), `product-details.tsx` (description as plain text, specifications as a definition list), `json-ld.tsx` (the ONLY `dangerouslySetInnerHTML`, fed by `serializeJsonLd`).
- Client islands: `product-purchase.tsx` (gallery, title, price, availability, option radio groups, quantity, add to cart, `role="status"` live region; `ProductPurchaseView` is the testable part), `store-image.tsx` (`next/image` with a placeholder for a missing, disallowed or failing image), `cart-badge.tsx` (`GET /store/cart` once per page load and the cart-changed event), `account-link.tsx` (`GET /store/account/me`, 401 = guest), `locale-switcher.tsx` (same page in the other locale, query kept), `i18n-provider.tsx` (translator of the page locale from the client message subset). The `*View` components are pure and are what the tests render.
- `status-views.tsx` - error, not-found and loading views (props in, markup out). `styles.ts` - shared class strings (tokens only).
- `test-helpers.ts` - sentinel translator and leftover-text helpers for the "no hardcoded text" tests. `shell.spec.tsx` - landmarks, skip link, islands, home outline, status views. `catalog.spec.tsx` - cards, grid, catalog view, filled home sections, the purchase island, product details, JSON-LD and `StoreImage` (markup, ARIA, no hardcoded text).

## `src/lib` (logic; no markup)
- `money.ts` - `formatMoney`, `minorUnitsToDecimalString`, `currencyExponent`: BigInt/string arithmetic, `Intl.NumberFormat` on the decimal string; never a float, never adds or multiplies money. `date.ts` - `formatDate`, `formatDateTime`.
- `problem-messages.ts` - maps problem `code`, `rule` and `errors[].code` to message keys (`errors.<code>`, `errors.rule.<rule>`, `errors.field.<code>`, `errors.generic`); never shows the API's `detail`. Spec compares the code list with `docs/api/openapi.json`.
- `store-data.ts` - `createStoreData` (catalog reads through `@fluxkit/api-client` with `?locale=`, no cookies, `next: {revalidate: 60, tags}` or the caller's `revalidateSeconds` (the sitemap uses 3600), last-good fallback in memory, `StoreUnavailableError`) and `ensureLocalesSupported`. `store-data.server.ts` - the wired instance (`API_INTERNAL_URL` per request, `connection()` before any read): server code only. `navigation-categories.ts` - header categories, `null` on an outage.
- Catalog logic (pure, unit-tested): `variant-matcher.ts` (`findVariant`, `initialSelection`, `isValueAvailable`, `selectValue`, `selectedValueIds`: option and value CODES are data, a value of option N is available only if a variant has it with the choices before it, so the picker cannot dead-end), `catalog-query.ts` (page size 24, the API's offset cap, `parseCatalogQuery`, `catalogPath`, page-range rules), `catalog-data.ts` (what each route loads through `StoreData`: `loadHomeData`, `loadCatalogListing`, `loadProductPage`), `category-trail.ts` (breadcrumb trails), `attributes.ts` (specification rows from the API's definitions), `availability.ts` (status to message key and badge variant; add button rule), `product-media.ts` (gallery order and host check), `image-source.ts` (https host allow-list, no credentials or port), `add-to-cart.ts` (`POST /store/cart/items` from the browser, problems to message keys), `cart-events.ts` (the cart-changed browser event).
- SEO: `seo.ts` (`absoluteUrl`, `languageAlternates`, `listingRobots`, `trimDescription`, `serializeJsonLd`, `productJsonLd`, `breadcrumbJsonLd`, `socialImageUrl`; prices are decimal strings from `minorUnitsToDecimalString`), `page-metadata.ts` (`homeMetadata`, `listingMetadata`, `productMetadata`), `sitemap.ts` (paging through the products, building the entries), `robots.ts`.
- Server wiring (server code only): `catalog-pages.server.ts` (React `cache` around the page loaders so a page and its `generateMetadata` share one load), `public-url.server.ts` (`publicOrigin`), `image-hosts.server.ts` (`imageHosts()` from the live environment), `sitemap.server.ts`. `test-fixtures.ts` - API-shaped sample data for tests (the only source file allowed to name options).
- `locale-check.ts` - `LocaleMismatchError`, `assertLocalesSupported`. `locale-path.ts` - `switchLocalePath`, `localizedHref` (plain storefront paths only). `session-state.ts` - the cart badge and account link loaders (browser, `no-store`) and `watchCartBadge` (first read plus cart-changed events). `client-messages.ts` - the message namespaces sent to the browser.
- `src/client-boundary.spec.ts` - no `'use client'` file imports server-only wiring, `@fluxkit/config`, `@fluxkit/core` or `next/server`; nothing imports `@fluxkit/core`; every message key a client file writes out is in a serialized namespace. `src/route-structure.spec.ts` - no `loading.tsx` above a route that can be not found. `src/source-guards.spec.ts` - `dangerouslySetInnerHTML` only in `json-ld.tsx`, no niche-specific option names, no float money math, `next/image` only in `store-image.tsx`.

## Configuration (internal, not a public contract in v1)
- `src/layout/home.ts` - the home sections in order with props (`categoryTiles {limit}`, `newProducts {limit}`). `src/layout/navigation.ts` - header and footer links (message keys, locale-less paths), `MAIN_CONTENT_ID`, the session link targets. `src/config/checkout.ts` - allowed shipping countries, default country `UA`, address fields shown (consumed by step 7). `layout/layout-config.spec.ts` checks keys, paths and defaults.

## `src/messages`
- `uk.json`, `en.json` - every user-facing string; `index.ts` maps locale to messages; `messages.spec.ts` - same keys, same `{placeholders}`, complete plural forms (uk one/few/many/other, en one/other), and every key-like literal in the source exists.

Run: `pnpm --filter @fluxkit/storefront dev -p 3001` (needs `pnpm build` once so workspace packages are built, and `API_INTERNAL_URL` in the root `.env` or the shell; the API on port 3000 with `STORE_COOKIE_SECURE=false`). Next telemetry is disabled in the scripts.

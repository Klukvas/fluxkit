# packages/ui

Dumb, token-styled components: props in, markup out. No fetching, no API types, no hardcoded user-facing strings (labels and aria texts come from props), semantic Tailwind utilities only (guarded by `packages/theme/src/design-guard.spec.ts`). Radii are roles since 2026-11-09: `rounded-control` (`button.tsx`, `controlBase` in `styles.ts`, fields, chips), `rounded-card`, `rounded-panel` (`alert.tsx`, `trust-bar.tsx`, the `data-table.tsx` scroll hint), `rounded-overlay` (`dialog.tsx`), `rounded-media` (`product-image.tsx`, `skeleton.tsx`); `checkbox.tsx`, `badge.tsx` and `price-text.tsx` keep `rounded-sm` (0.25rem) as listed guard exceptions (`docs/contracts/theme-tokens.md`, "Radius roles").

- `src/index.ts` - public entry point; other packages import only from here.
- `src/cn.ts`, `src/styles.ts` - class joiner; shared focus ring (`outline-ring`) and form-control classes.
- `src/i18n.ts` - `locales`, `defaultLocale`, `isLocale`, `createTranslator(messages, locale?)` (`t(key, values)` with `{name}` interpolation, `t.plural(key, count, values)` with `<key>.<one|few|many|other>` forms from `Intl.PluralRules`; a missing key, form or placeholder value throws), `messagePlaceholders`.
- `src/button.tsx`, `src/card.tsx`, `src/container.tsx` - primitives.
- `src/input.tsx`, `src/textarea.tsx`, `src/select.tsx`, `src/checkbox.tsx` - form controls (`forwardRef`, native attributes; invalid style follows `aria-invalid`). Their border is `border-border-input` (3:1, WCAG 1.4.11), not the decorative `border-border`; the quantity field uses it too.
- `src/field.tsx` - label, hint and error around a control; passes `id`, `aria-describedby`, `aria-invalid`, `required` to its render-prop child.
- `src/alert.tsx` - `info`/`success`/`warning`/`danger`; `danger` is `role="alert"`, the others `role="status"`.
- `src/badge.tsx`, `src/spinner.tsx` (name from `label`), `src/skeleton.tsx` (decorative, `aria-hidden`), `src/empty-state.tsx`.
- `src/price-text.tsx` - preformatted price plus optional struck-through compare-at with spoken text from props. Must NOT format money.
- `src/quantity-input.tsx` - number input with labelled minus/plus buttons, `min`/`max`, optional `stepMax` (where the buttons stop, e.g. a stock hint; a typed number is clamped to `max` only), `clampQuantity`.
- `src/pagination.tsx` (`aria-current`, disabled previous/next, `pageItems`), `src/breadcrumbs.tsx` (last item is `aria-current="page"`; links at least 24 px high, 44 px on `pointer: coarse`).
- `src/checkbox.tsx` `fullWidth` (2026-11-03): the label, the hit area, takes the whole row; `src/button.tsx` takes `ref` as a prop (React 19, `ComponentPropsWithRef<"button">`).
- `src/product-image.tsx` - lazy image with a token-styled placeholder when `src` is missing or fails. Image and placeholder use `rounded-media`. A client component (`"use client"`): the failing-image fallback needs state and `onError`. `Dialog` and `Tabs` are the other two.
- `src/option-picker.tsx` - radio group per product option in a `fieldset`/`legend`; disabled values are struck through, not only dimmed.
- `src/skip-link.tsx`, `src/visually-hidden.tsx` - accessibility helpers.
- Admin components (admin UI plan step 4a; props in, markup out, no fetching, labels and aria texts from props):
  - `src/data-table.tsx` - generic `DataTable<Row>`: caption (optionally visually hidden), `th scope="col"` headers from props, a row header (`th scope="row"`, first column or `rowHeaderColumnId`) per row, one empty-state row spanning the table, skeleton rows with `aria-busy` while `loading`, optional actions column. No sorting, paging or fetching; throws for an unknown row header column. The scroll box is `relative`, so its visually hidden texts never widen the page, and a focusable region named by the caption (keyboard scrolling in Firefox and Safari; always a Tab stop); `DataTableScrollHint` (context) is the app's "swipe sideways" text, shown above every table below 768 px.
  - `src/dialog.tsx` - `Dialog`: native `<dialog>` opened with `showModal()` from an effect (client component, like `ProductImage`); controlled by `open`; Escape calls `onClose` (the native cancel is prevented, the state stays the source of truth); a backdrop click does nothing; title through `aria-labelledby`, optional description through `aria-describedby`; never renders the `open` attribute.
  - `src/dialog-focus.ts` - pure `openModal(dialog, opener)` (show once, focus `[data-autofocus]`, return a closer that closes and returns the focus to a still-connected opener) and `nativeCloseAction` (what a native `close` event does: ignored while the state is closed or the element is open again, the stale event of React StrictMode's effect re-run; else close or reopen), unit tested with fakes, no DOM.
  - `src/confirm-dialog.tsx` - `ConfirmDialog`: `alertdialog` with cancel and confirm buttons (labels from props), `tone="danger"`, `busy` (both buttons disabled, `aria-busy`, Escape ignored); focus starts on cancel.
  - `src/tabs.tsx` - `Tabs`: WAI-ARIA tabs (`tablist`, `tab`, one `tabpanel`), controlled, roving tabindex, arrows/Home/End select (client component). Only the selected panel is rendered, so only the selected tab has `aria-controls`.
  - `src/tab-navigation.ts` - pure `nextTabIndex(current, key, disabled)` (wrap-around, disabled tabs skipped, `null` for other keys).
  - `src/description-list.tsx` - `DescriptionList` (`dl`/`dt`/`dd` pairs from `items`).
  - `src/filter-bar.tsx` - `FilterBar`: a labelled `form` region (not `role="toolbar"`, which promises arrow-key navigation); native form attributes pass through except `method`, which is always `post` (the storefront source guard requires it for every `<form>` in the repository).
  - `src/side-nav.tsx` - `SideNav`: labelled `nav`, groups with optional headings (`ul` labelled by the heading), `aria-current="page"` on the current item, links through `renderLink` (the app passes its router's link; no router dependency).
  - `src/locale-text-field.tsx` - `LocaleTextField`: one `Field` + `Input` or `Textarea` per content locale in a `fieldset`/`legend`, `lang` per control, per-locale hint and error through `aria-describedby`, `required` only where the props say (the default locale), `readOnly`.
  - `src/status-badge.tsx` - `StatusBadge` (tone + visible text, on `Badge`); `src/live-region.tsx` - `LiveRegion` (`role="status"`, `aria-live="polite"`, `aria-atomic`, optional visually hidden; render it before its content changes).
- `src/button.tsx` also has a `danger` variant (outlined with the danger token; the theme has no on-danger text color).
- Design kit (design batch A, 2026-11-03, plan `docs/plans/2026-11-03-storefront-design-a.md`):
  - `src/styles.ts` `textStyles` - text roles as class strings (`pageTitle`, `pageTitleCompact`, `sectionTitle`, `subsectionTitle`, `itemTitle`, `cardTitle`, `dialogTitle`, `navGroupTitle`, `meta`; 2026-11-08), built from the type-scale and colour tokens; `font-display` only on `pageTitle` and `sectionTitle`. Every heading and legend of ui and the storefront starts from a role (design guard); `design-kit.spec.tsx` checks the roles, not exact strings.
  - `src/button.tsx` - `size` (`md` default, unchanged; `lg` 48 px) and a hover state only while enabled (`enabled:hover:`); no colour transition (it would animate the focus ring).
  - `src/price-text.tsx` - optional `discount` (`{text, label}`: the visible badge is `aria-hidden`, the label is read); only with a compare-at price. Computes nothing.
  - `src/option-picker.tsx` - `soldOut` values: struck through and muted but selectable; `soldOutLabel` is the radio's description (`aria-describedby` to a hidden element outside the label), so the value's name stays the same.
  - `src/trust-bar.tsx` - `TrustBar`: a labelled list of decorative icon + text items; renders nothing without items.
  - `src/hero.tsx` - `Hero` (design batch B): a `section` labelled by its `h1` or `h2`, subline, an action and a picture slot (rendered by the app) on the `muted` surface, two columns from `md`, text first on a phone. The home page's `hero` sections and the category banner. Must NOT know copy, routing or image hosts.
  - `src/banner-card.tsx` - `BannerCard` (admin home banners plan, section 7): one home page promotional banner as ONE link rendered by the app (`renderLink`: a router link, a plain anchor, or a non-link in a preview). `card`: picture in a fixed 2:1 frame (`aspect-2/1`, the app's `img` fills it with `object-cover`), title (`h3` by default, the link's name via `aria-labelledby`) and optional text (`aria-describedby`), tone `surface` or `accent` (the `--fk-color-accent` pair since 2026-11-08, equal to primary by default; the tone name is unchanged because the API stores it); `image`: the picture alone, named by its alt, no tone. Used by the storefront's `BannersView` (both sources) and the admin's live preview, so both draw the same card. Tokens only; must NOT know copy, routing, image hosts or the locale. Tests: `banner-card.spec.tsx`, `no-hardcoded-text.spec.tsx`.
  - `src/step-indicator.tsx` - `StepIndicator`: an `ol` in a labelled `nav`, `aria-current="step"`, completed steps linked when given an `href` and named with `completedLabel`; below `md` only the `compactText` line is shown (the list stays for assistive technology).
  - `src/disclosure.tsx` - `Disclosure`: a native `<details>` section, open by default, with a real heading in its `summary` and a labelled region; works without a script.
  - `src/design-kit.spec.tsx` - their markup, ARIA and classes; `no-hardcoded-text.spec.tsx` renders each with sentinels.
- `src/*.spec.ts(x)` - Vitest with `renderToStaticMarkup` (no DOM library); `src/test-helpers.ts` (not built) parses the markup. `no-hardcoded-text.spec.tsx` renders every component (the admin ones included, with loading, empty, busy and multiline variants) with sentinel strings and fails on any other text. Admin component specs: `admin-data.spec.tsx`, `admin-nav.spec.tsx`, `dialog.spec.tsx`, `tabs.spec.tsx`, `locale-text-field.spec.tsx`, `tab-navigation.spec.ts`, `dialog-focus.spec.ts`.
- Built with `tsc` to `dist/` (bundler resolution, consumed by Next and Vite).

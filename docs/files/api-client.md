# packages/api-client

Typed clients for the public store API (`createStoreClient`) and the admin API (`createAdminClient`). No runtime dependency. Details and the generator decision: `packages/api-client/README.md`.

- `src/index.ts` - the public exports (both clients, errors, `OPERATIONS`, `ADMIN_OPERATIONS`, types). Import only from here.
- `src/client.ts` - `createStoreClient({ baseUrl, fetch? })`: one function per store operation and the idempotency key check (since shipping plan step 6 also `getShippingOptions`, `listShippingCities` and `listShippingPickupPoints`, added because the contract test covers every `/store` operation; the storefront does not call them yet, plan steps 9b and 10). Must NOT parse responses, build URLs or import an admin module.
- `src/transport.ts` - `createTransport`: refuses raw bytes for any operation that is not `binary` (and a JSON body for one that is), builds the request (`buildRequest`), sends it with exactly one `fetch` call, throws a rejected `fetch` as `NetworkError`, hands the answer to `parseResponse`; also `FetchLike` and `CallOptions`. Shared by both clients. Must NOT retry, replay or log.
- `src/admin-client.ts` - `createAdminClient({ baseUrl, fetch? })`: one function per `/admin` operation (108, `uploadMedia` among them, the eight shipping settings operations `createShippingMethod` ... `checkShippingProvider`, all `shipping.manage`, and the eight email operations `getEmailStatus` ... `previewEmailTemplate`, all `email.manage`: raw bytes, no retry, `signal` to cancel, no progress), typed filter options (`AdminListProductsOptions`, ...), `AdminResult<T>`. Must NOT parse responses, build URLs or import the store client.
- `src/admin-operations.ts` - `ADMIN_OPERATIONS`: method, path, success statuses, query parameters, body kind (`none`, `json`, `binary`), response kind (`json`, or `pdf` for the shipment label only) and `x-fluxkit-permission` of each admin operation; checked against `docs/api/openapi.json`.
- `src/admin-types.ts` - hand-written admin request and response types (`AdminProduct`, `AdminVariant`, `AdminOrder`, `AdminConfig`, ...). Must stay equal to the OpenAPI schemas (the admin contract test enforces it).
- `src/request.ts` - `buildRequest`: URL, path parameter and query encoding, `X-Fluxkit-CSRF: 1` on every non-GET/HEAD request, JSON content type only with a JSON body, or `application/octet-stream` with a `rawBody` (the upload; the only way to send non-JSON), same-origin credentials. Pure and unit tested.
- `src/response.ts` - `parseResponse`: documented success to `{ ok: true }` (a `pdf` operation: an `application/pdf` body as a `Blob`, anything else thrown), `application/problem+json` to `{ ok: false, problem, retryAfter }`, everything else thrown. Must NOT log or return a response body in an error.
- `src/errors.ts` - `ApiClientError` (base class), `InvalidRequestError`, `NetworkError`, `InvalidResponseError`.
- `src/operations.ts` - `OPERATIONS`: method, path, success statuses, query parameters and body flag of each store operation; checked against `docs/api/openapi.json`.
- `src/types.ts` - hand-written store request and response types (`Cart`, `Order` with its `shipping` snapshot, `CheckoutBody` with `shipping`, `ShippingOption`, `ShippingOptions`, `ShippingChanged`, the lookup pages, `ProblemDetails` with the shipping codes and member, ...); `Money`, `Address`, `OrderStatus`, `OrderContact` and `ProblemDetails` are shared with the admin types. Must stay equal to the OpenAPI schemas (the contract test enforces it).
- `src/testing/shape.ts` - test support (`Shape<T>`, `compareShape`; `JsonValue` is the shape `"any"`, a boolean literal such as `ok: true` is `{literal}`); excluded from the build.
- `src/*.spec.ts` - unit tests (`request`, `response`, `transport`, `client` and `admin-client` with an injected `fetch`), `contract.spec.ts` and `admin-contract.spec.ts` (types and operations versus `docs/api/openapi.json`), and `bundle-boundary.spec.ts` (the admin modules stay out of the store client's import graph; `sideEffects: false`).
- `tsconfig.build.json` - the build config; leaves out specs and `src/testing`.

# 0030. Nova Post API for the first carrier plugin

Status: accepted 2026-10-25 (owner decision: build the plugin on the new Nova Post API). Supersedes in part ADR 0029: decision 11 (the Nova Poshta plugin) as a whole, and the Nova Poshta specific sentences of decisions 7 (`provider_service` values, the `shipping_provider_setting` field list) and 8 (the variable `NOVA_POSHTA_API_KEY`). Every other decision of ADR 0029, including the shape of `ShippingProviderPort` (decision 9) and polling (decision 10), stays; the port changes proposed below are decided at plan step 7b with the evidence of the spike. ADR 0029 itself is not edited.

Nothing here is built yet. Facts below cite the official documentation (portal `https://api-portal.novapost.com`, read 2026-10-25 through its Markdown pages listed in `https://api-portal.novapost.com/llms.txt`) or the key-less probes of 2026-10-25 (plan section 8, "Key-less findings"). Anything the documents do not state is marked UNKNOWN.

## Context

- **The owner's key belongs to the new API.** It works with `GET https://api.novapost.com/v.1.0/clients/authorization?apiKey=<key>` (answers `{jwt}`) and then with `GET /divisions`, `/settlements`, `/shipments` and `/clients` with the JWT in the `Authorization` header; the legacy routes (`/cities` and the like) do not exist there (owner's observation, 2026-10-25). ADR 0029 decision 11 and the plan's section 8 were written from memory for the legacy JSON-RPC API (`https://api.novaposhta.ua/v2.0/json/`); the key does not fit them.
- **What the documents say about the two APIs.** The legacy API is "API 2.0" for domestic shipments within Ukraine, documented in the local language only, and "always returns an HTTP 200 OK" ([general information](https://api-portal.novapost.com/api-docs-ua/eng/general-information.md)). The same page says the international API "is under active development and is gradually expanding to support domestic shipments within Ukraine", "will become the single unified API", and recommends it "for new integrations". No page calls API 2.0 deprecated or names an end date: **UNKNOWN**.
- **Endpoints.** `https://api.novapost.com/v.1.0` serves "all delivery destinations without restrictions, including ... domestic deliveries within Ukraine"; a second endpoint `https://api.novaposhta.ua/v.1.0` serves "only ... domestic shipments within Ukraine or ... from Ukraine" ([choosing the endpoint](https://api-portal.novapost.com/novaposhta-docs/integration-guide/how-to-choose-the-appropriate-endpoint.md)). How the two differ beyond that: UNKNOWN.
- **Authorization.** `GET /clients/authorization?apiKey=` issues a JWT "valid for ~1 hour; request a new one after expiry; do not store jwt beyond its TTL", sent as `Authorization: {jwt}` ([authorization](https://api-portal.novapost.com/methods/methods/authorization.md)); "the maximum number of active sessions (tokens) per account may be limited" ([using tokens](https://api-portal.novapost.com/novaposhta-docs/integration-guide/using-tokens.md)). Other pages write `Authorization: Bearer {JWT_TOKEN}` ([help center](https://api-portal.novapost.com/help-center/readme.md), [API errors](https://api-portal.novapost.com/methods/methods/api-errors.md)); the owner's working calls send the raw JWT. Keys are issued to a natural person; for Ukrainian clients in the business cabinet `new.novaposhta.ua`, "Settings - Security"; the key list shows a validity period ([API key generation](https://api-portal.novapost.com/novaposhta-docs/integration-guide/api-key-generation.md)).
- **A sandbox exists.** Base URL `https://api-stage.novapost.com/v.1.0/` in the OpenAPI blocks of every method page and in the webhooks page; the testing page and two other pages name `api-stage.novapost.pl` ([testing](https://api-portal.novapost.com/novaposhta-docs/integration-guide/testing.md)). Both hosts answer (key-less probes). Sandbox keys are separate: `POST /test-api-keys` with a phone registered at `my.novapost.com`, one request a day, and "UA key generation is currently not supported" ([API key generation](https://api-portal.novapost.com/novaposhta-docs/integration-guide/api-key-generation.md)).
- **Webhooks exist** (`/tracking-push/subscribers`, retries up to 6 times, `x-np-attempt` for de-duplication, a shared secret header; "In Sandbox only the test webhook can be sent") ([webhooks](https://api-portal.novapost.com/methods/methods/webhooks.md)).
- **Directories, shipments, tracking, labels** are REST routes with integer settlement and division ids, inline sender and recipient data (no counterparty or contact refs), ISO 8601 UTC times, `{errors: {...}}` bodies with real HTTP statuses (plan section 8 has the route-by-route evidence).

## Decision

1. **The first carrier plugin targets the new Nova Post API** (`https://api.novapost.com/v.1.0`, REST and JWT). The legacy JSON-RPC API is not supported in v1; no legacy plugin is built. A shop that has only a legacy key needs a new-API key.
2. **Naming follows the brand of the API:** provider code `nova_post`, package `packages/providers/nova-post`, key variable `NOVA_POST_API_KEY` (replaces the never-built `NOVA_POSHTA_API_KEY` of ADR 0029 decision 8). The environment is chosen by an enumerated variable (proposal: `NOVA_POST_ENVIRONMENT=sandbox|production`) that selects one of two base-URL constants in the package; no URL is configurable (no SSRF). The exact configuration is decided and added in plan step 7b (config schema, red zone).
3. **Base URL constants:** production `https://api.novapost.com/v.1.0`; sandbox `https://api-stage.novapost.com/v.1.0` (the host most pages name). The second Ukrainian endpoint `https://api.novaposhta.ua/v.1.0` is not used in v1.
4. **Authorization:** the plugin exchanges the key for a JWT, caches it in memory per process until shortly before it expires (from the token's `exp` claim when present, else 50 minutes), refreshes once on a `401`, and never stores or logs the key, the JWT or the URL of the authorization call (the key travels in its query string). The header form (raw or `Bearer`) is the one the spike finds accepted (hypothesis H04).
5. **Tracking stays polling** (ADR 0029 decision 10 unchanged). Webhooks need a public HTTPS endpoint, a shared secret and a subscription lifecycle; they are later work with their own plan.
6. **Legacy spike tool is deprecated and kept for history:** `scripts/spikes/nova-poshta-verify.mjs` stays in the repository with a deprecation header; the new tool is `scripts/spikes/nova-post-verify.mjs`.

## Deviations from ADR 0029 decision 11 and from the current port

| ADR 0029 / port | New Nova Post API (evidence) | Consequence |
|---|---|---|
| One JSON-RPC endpoint, key in the body | REST routes; key only in the query of `GET /clients/authorization`; JWT header on every other call ([authorization](https://api-portal.novapost.com/methods/methods/authorization.md)) | Never log URLs of the authorization call; JWT cache and refresh (decision 4) |
| HTTP 200 for every error | `401` "Invalid token", `404`, `422` with `{errors: {<field> or errorMessage: text}}`, `429` "Too Many Attempts." (per-minute limit), `502`, `503` ([API errors](https://api-portal.novapost.com/methods/methods/api-errors.md); key-less probes) | Map by HTTP status first; carrier codes are field names and snake_case `errorMessage` values only, never free text |
| No sandbox | Sandbox with its own keys; UA test keys "currently not supported" | The spike's write stage defaults to the sandbox and refuses production without an extra flag; whether a UA sandbox key can be obtained is open (owner) |
| No webhooks | Webhooks exist ([webhooks](https://api-portal.novapost.com/methods/methods/webhooks.md)) | Not used in v1 (decision 5) |
| No idempotency key for creation | Still none documented on any shipment page | `pending` / `unknown` / `reconcile` stay |
| Refs are uuids | Settlement and division ids are integers; `externalId` (the old uuid) must not be used ([externalId checklist](https://api-portal.novapost.com/checklists/change-in-the-semantics-of-the-externalid-field-in-the-division-directory.md)); the shipment id is a uuid in the create answer but `int32` in the `ids[]` filter of `GET /shipments` ([shipments](https://api-portal.novapost.com/methods/methods/shipments.md)) | `CARRIER_REFERENCE_PATTERN` already admits digits; the uuid/int conflict is spike hypothesis H24 |
| Recipient through `Counterparty.save`, sender counterparty and contact refs | Inline `sender` and `recipient` objects: name (max 100), phone (E.164), email, `companyTin`/`companyName` for a legal entity, `divisionId` or `addressParts` ([domestic shipments](https://api-portal.novapost.com/methods/methods/shipments/create-shipments/domestic-shipments-within-ukraine.md)) | The provider settings become a sender profile without refs (plan section 8); `WaybillRequest.recipient` first and last name are joined into `name` |
| Waybill found by `InfoRegClientBarcodes` and `getDocumentList` over Kyiv dates | `clientOrder` (max 50) is stored; `GET /shipments` filters only by `numbers[]`, `ids[]`, `senderDivisionId`, page and limit: no reference or date filter; times are ISO 8601 UTC | `findWaybill` pages the list and matches `clientOrder` and `createdAt` inside the instant window; page order and depth are spike hypothesis H23 |
| Tracking without a key, `Documents [{DocumentNumber, Phone}]`, 100 per call | `GET /shipments/tracking` and `/shipments/tracking/history` with `numbers[]` and the JWT; status codes are digit strings with a documented table ([tracking](https://api-portal.novapost.com/methods/methods/shipments/tracking-shipment.md)); the batch limit is not documented (UNKNOWN) | `track` ignores `phones`; `maxTrackingNumbersPerCall` stays 100 until the spike measures |
| Label URLs on `my.novaposhta.ua` with the key in the path | `GET /shipments/print?numbers[]=<number>&type[]=marking`, PDF, one number per marking request, with the JWT ([marking labels](https://api-portal.novapost.com/methods/methods/shipments/print-documents/marking-labels.md)) | No key in any URL; the port's `fetchLabel` needs the waybill NUMBER (it takes `providerRef`, the id): proposed port change at 7b |
| Cancel with `InternetDocument.delete` | `DELETE /shipments/{id}`; for Ukraine by id only, not by number; a repeat answers `422 shipment_was_deleted`, an unknown id `404 shipment_not_found` ([shipments](https://api-portal.novapost.com/methods/methods/shipments.md), [changelog](https://api-portal.novapost.com/changelog-1/documentation-eng/returning-doc-was-deleted-response-for-repeated-deletion-of-a-shipment.md)) | `cancelWaybill` treats `shipment_was_deleted` as done |
| City search `Address.searchSettlements`, branches `Address.getWarehouses` | `GET /settlements?textSearch=` and `GET /divisions?settlementIds[]=&divisionCategories[]=` (Postomat, PostBranch, CargoBranch, PUDO), paged `{current_page, last_page, per_page, total, items}`, default 15 per page ([dictionaries](https://api-portal.novapost.com/methods/methods/dictionaries.md)) | No documented lookup of one division by id: `findPickupPoint` needs either an undocumented filter (spike H16) or a composite ref that carries the settlement id (plan section 8) |
| Price `InternetDocument.getDocumentPrice` (UAH decimals) | `POST /shipments/calculations`: `services[].cost` numbers; the answer names no currency; its changelog lists the direction "UA-EU (US)" ([delivery cost](https://api-portal.novapost.com/methods/methods/shipments/delivery-cost.md)) | Whether domestic UA is priced and in which currency is UNKNOWN (spike H18); the estimate is informational only, so a missing estimate is `null` |
| No English names | `GET /divisions` takes `Accept-language` with `uk` and `en` among 15 languages; `/settlements` documents none | Locale handling decided after H11 and H14 |
| `provider_service` `warehouse`, `postomat`, `doors` | No such codes; division categories and `addressParts` delivery | Service codes are redefined in 7b |
| Keys can expire | The cabinet lists a validity period; an invented key answers `422 "API key expired"`; "Jwt creation is not allowed, api key status is <status>" exists | Both map to `invalid_credentials` |
| Directory storage terms unknown | An offline divisions dictionary is published for "offline use and periodic synchronization" (key-less, a 302 to a CDN, about 33 MB gzip for all countries) | The in-process cache of ADR 0029 decision 6 stays; a synced table remains a later option; the legal question stays open |

## Consequences

- **Plan:** section 8 and steps 7a and 7b of `docs/plans/2026-10-24-shipping.md` are rewritten for the new API; the legacy findings stay there as superseded history.
- **Spike:** `scripts/spikes/nova-post-verify.mjs` (stages `keyless`, `readonly`, `write --confirm`, sandbox by default) replaces the legacy tool; its hypotheses H01 to H35 cite these documents.
- **Owner actions before 7a-write:** a sandbox key if one can be obtained for a Ukrainian account (else an explicit decision to run the write stage on production with `--allow-production-write`), and the sender profile data (name, phone, optional email, company TIN and name for a legal entity, the sender division id, an optional contract number for non-cash payment). Nothing has to be created as a counterparty in the cabinet.
- **Port changes proposed for 7b (internal contract, approval with 7b):** `fetchLabel` takes the waybill number; `track` ignores phones; a settings validator member (open since step 5) to check the sender profile; possibly a composite pickup point ref. The ADR 0029 decision 9 shape otherwise stays.
- **Configuration (red zone, 7b):** `NOVA_POST_API_KEY` and the environment selector, added to `.env.example`, `docs/contracts/config.md` and the AGENTS.md list by the owner.
- **Risks:** the new API is "under active development" for Ukrainian domestic delivery, so routes may change (the changelog is the place to watch); the documents disagree on the sandbox host and on the `Authorization` form; whether creating and deleting a production shipment costs anything is not documented (UNKNOWN); a UA sandbox key may not be available, which leaves the write stage to production; `findWaybill` without a filter may need to read several pages.
- **What would supersede this ADR:** Nova Post documenting idempotency or a reference filter for shipments, a Ukrainian sandbox, a deprecation of `v.1.0`, or a decision to use webhooks.

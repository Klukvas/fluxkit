Branch `fix/ux-repairs-1` from `origin/main` `3760110`. Source: the owner's UX review of 2026-11-05/06 (simulated shop managers Olena and Taras,
shopper Iryna) and a debugger's finding. Admin app and `@fluxkit/ui` only; investigation only for payments, rate limits and the product card.

## Goal

Fix the admin defects and rough edges the review found, without touching money, payment or auth logic, and record what the payment, rate-limit and
product-card findings really are.

## Found (existing functionality)

- Dialogs: `packages/ui/src/dialog.tsx` (native `<dialog>`, controlled `open`), the open/close logic in `packages/ui/src/dialog-focus.ts` (`openModal`, pure,
  spec `dialog-focus.spec.ts`). `apps/admin/src/main.tsx` renders under `StrictMode`, so in `vite dev` the open effect runs, is cleaned up (`dialog.close()`
  queues a native `close` event) and runs again; the queued event then reaches `onClose` while the dialog is open again and the state is closed.
- Variants tab: `apps/admin/src/areas/products/tabs/variants-tab.tsx`, model `variant-form.ts` (`combinationTaken`, `validateVariantCreate`). Help article
  "Вкладка Варіанти" in `apps/admin/src/areas/help/content/catalog.ts`.
- Banners: `apps/admin/src/areas/banners/` (`banner-list-view.tsx`, `banner-form.ts`, `banner-form-view.tsx`, `banner-editor-pages.tsx`), core rule
  `packages/core/src/content/banner-content.ts`: the API requires the alt text of an `image` banner in the DEFAULT locale only; the form additionally requires
  every language's naming text to switch a banner on (owner plan `2026-11-05-admin-home-banners.md`, section 7, "both languages required to activate").
  The form summary is focused by `useFormSubmit` (`areas/catalog-dictionaries/use-form-submit.ts`), never the field.
- Prices: `apps/admin/src/areas/products/prices/` (`price-grid.ts` `planPriceSave`, `prices-tab.tsx`); variant activation in `variants-tab.tsx`
  (`onToggleActive`); product publish in `lifecycle.ts` and the editor.
- Shell: `apps/admin/src/layout/shell.tsx` (`ShellFrame`, `SideNav` of `@fluxkit/ui`); `DataTable` already wraps tables in `overflow-x-auto`; `Tabs`
  (`packages/ui/src/tabs.tsx`) wraps its tab list.
- UI language: `apps/admin/src/i18n/locale-preference.ts` already remembers the choice in `localStorage` (try/catch) and falls back to the browser language.
- Product form: `product-general-view.tsx` has local validation (`validateProductForm`, title limit 255) but no `noValidate`.
- Orders: the paid-cancel warning exists (`order.cancel.paidTitle/paidBody`), behaviour per `docs/api/orders.md` "Cancel of a paid order": nothing restocked,
  nothing refunded. Payment panel `apps/admin/src/areas/payments/payment-panel.tsx`; attention texts in `messages/*/payments.json`.
- Shipping form labels `messages/*/shipping.json` (`ship.form.providerCode`, `providerService`, `countriesHint`, `ship.pricing.type`); Email status
  `areas/email/status-view.tsx` (`mail.setup.*`).

## Risks

- Item 1 changes a shared UI component used by every dialog of both apps; Escape, the backdrop and the not-dismissible path are covered by the existing
  specs plus the new pure spec.
- Item 3c changes where the focus goes after a local refusal in every form that uses `showIssues` only where the caller asks for it (opt-in), so other
  forms keep focusing the summary.
- Item 4 adds a step to saving a 0 price; e2e scenarios that save 0 (none known) would need to confirm.
- Item 5 changes the shell markup on small screens; desktop layout unchanged (checked with screenshots).
- Verification gap: this sandbox cannot start Postgres (see Results), so the e2e suites and the API integration tests cannot run here.

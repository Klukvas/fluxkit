## Owner decisions (quiz 2026-10-18)
1. **Guest access token on a replay**: the token is deterministic, an HMAC over the order id and the idempotency key with a new secret, so a replay returns the SAME token and both answers of a double submit work. Only the hash is stored, as today. New secret env var (red zone, approved here).
2. **Unpaid orders holding stock**: limit the number of open (`awaiting_payment`) orders per guest email and per customer (configurable, default 3). No new schema; the per-IP rate limit stays. A per-IP open-order count would need an IP column on the order and is NOT done (recorded as a known gap).

## PRs (in order, one branch each, merge only on the owner's word)
- **A. Stable guest token on replay** (review High 1): ADR 0023, `ORDER_TOKEN_SECRET` (min length, required in production like the other secrets; `.env.example`, `docs/contracts/config.md`, README), token derivation in core (pure, secret passed in), checkout stores the hash at placement and a replay returns the same token without rotating; expiry unchanged; tests: parallel identical checkouts return the same working token in 20 rounds, token never logged or stored raw, secret rotation behavior documented.
- **B. Open-order limit and proxy-aware rate limits** (review High 2, Medium 4): `MAX_OPEN_ORDERS` (default 3, bounds in config), checked inside the checkout transaction (race-safe, under the cart/customer lock) with a typed refusal `too_many_open_orders` (documented); `TRUST_PROXY` setting (off by default; hops count) applied to Express so `request.ip` is the client address, documented for both admin and store limits; tests incl. parallel checkouts at the limit.
- **C. Reliability fixes** (review Medium 1 to 3 and the test gap): outbox dispatcher claims events and commits, runs handlers outside any open transaction, records the result in a short second transaction (attempts and backoff survive a failed batch); skipped scheduler ticks (`lock_held`, `overlap`) logged at debug/warn with a counter and a per-job statement timeout; checkout with a product title in a locale no longer in `LOCALES` falls back like the store read instead of 500 (snapshot builder rule); deterministic test for a variant deleted mid-checkout (`409 cart_changed`); cart read no longer 409s when a price raise overflows a line (the line is marked unavailable instead).
- Low findings are recorded in `docs/HANDOFF.md` as known gaps (not fixed here): header immutability and journal cascade/TRUNCATE, guest cancel locking before token check, `mark-fulfilled` after 365-day backorder, cookie-less cart rows, account lockout abuse, sibling-subdomain cart cookie, retry spacing anchored to creation, `occurredAt` semantics, down migration leaves reservations.
